# GUIDE — Yandex Maps API_KEY для прода (JS API + HTTP Геокодер + Геосаджест)

> Как получить и подключить **прод-ключ** Yandex Maps для `avino.uz`.
> Связано: ADR-0079 (геосаджест по Узбекистану), ADR-0147 (нормализация +
> геокодинг адреса объявления), `docs/ENV.md` §10, аналог по структуре —
> `docs/GUIDE_YANDEX_SMTP_SETUP.md`.

---

## 1. Что реально нужно проекту (и почему один кабинет, а не три)

В коде используются **три разных продукта Yandex Maps**, но с текущим дизайном
достаточно **одного ключа**, подключённого сразу к нескольким продуктам:

| Продукт Yandex | Где используется в коде | Env-переменная |
|---|---|---|
| **JavaScript API 2.1** (карта в браузере) | `apps/client` — `/map`, `/search`; `apps/web` (админка); загрузчик `useYmaps.ts` | `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` |
| **API Геосаджеста** (`ymaps.suggest`, автодополнение адреса) | `apps/client` — `Hero.tsx`, `FilterBar.tsx` (`useGeoSuggest`), ADR-0079 | тот же ключ, либо отдельно `NEXT_PUBLIC_YANDEX_SUGGEST_API_KEY` |
| **HTTP Геокодер API** (`geocode-maps.yandex.ru/1.x/`) | `apps/api` — `AddressResolverService` (`apps/api/src/geo/address-resolver.service.ts:19`), нормализация адреса при create/update листинга, ADR-0147 | `YANDEX_MAPS_API_KEY` (server-side, secret) |

Итого для прода нужны **два ключа-значения в env** (могут физически быть
одним и тем же ключом Yandex, если в кабинете он подключён ко всем трём
продуктам):

```
YANDEX_MAPS_API_KEY=<серверный ключ, HTTP Геокодер>
NEXT_PUBLIC_YANDEX_MAPS_API_KEY=<браузерный ключ, JS API + Геосаджест>
```

`NEXT_PUBLIC_*` **печётся в билд** фронтов (Docker build-arg) — смена требует
ребилда контейнера, не только рестарта. `YANDEX_MAPS_API_KEY` читается в
runtime `api` — смена требует только рестарта контейнера `api`.

## 2. Шаг 0 — кто регистрирует (владелец, не агент)

Как и с Yandex 360 (`docs/GUIDE_YANDEX_SMTP_SETUP.md` §2, Шаг 0): подключение
платного продукта и биллинга — юридически значимое действие с привязкой карты
и/или реквизитов юрлица. **Агент (Claude) этого не делает.**

- Роль агента: показать, куда зайти, что нажать, объяснить формы.
- Роль Team Lead: залогиниться под `avino.uz@yandex.com` (или другим
  владельцем организации), подтвердить продукт, привязать биллинг/карту.

## 3. Шаг 1 — получить ключ в кабинете разработчика

1. Открыть **Кабинет разработчика Яндекса**: https://developer.tech.yandex.ru/services
   (это актуальный кабинет для API Яндекс Карт; старый `passport-based`
   `yandex.ru/dev` теперь редиректит сюда).
2. Войти под аккаунтом-владельцем организации.
3. **Создать ключ** → выбрать продукт **«JavaScript API и HTTP Геокодер»**
   (в текущем кабинете это один пункт — оба API включаются одним ключом).
   - Указать сайт использования: `avino.uz`.
   - Описание: `avino prod` (чтобы отличать от dev/staging-ключа).
4. Дождаться активации — обычно мгновенно для JS API, до нескольких часов
   для HTTP Геокодера (модерация заявки Yandex).
5. Отдельно (или в том же ключе, если кабинет предлагает мультипродуктовые
   ключи) подключить **«API Геосаджеста»** — без него `ymaps.suggest` кидает
   `Suggest is not available` (см. ADR-0079, уже наступали на эти грабли на
   dev-ключе).

> Если кабинет не даёт добавить второй продукт к уже созданному ключу —
> создать второй ключ под Геосаджест и передать его отдельно через
> `NEXT_PUBLIC_YANDEX_SUGGEST_API_KEY` (код это уже поддерживает, см.
> `useYmaps.ts`: `SUGGEST_API_KEY = NEXT_PUBLIC_YANDEX_SUGGEST_API_KEY || NEXT_PUBLIC_YANDEX_MAPS_API_KEY`).

## 4. Шаг 2 — HTTP-Referer whitelist (обязательно для прод-домена)

В настройках ключа JS API/Геосаджеста задать список разрешённых доменов —
без этого браузерные запросы получают `403` (в консоли выглядит как
CORS-ошибка, у 403 нет CORS-заголовков — легко спутать с багом кода):

```
avino.uz
api.avino.uz
test.avino.uz
test-admin.avino.uz
localhost
avino.uz
*.avino.uz
localhost       # для локальной разработки/дева, если ключ шарится
75.119.159.168
```

Если dev/staging использует **отдельный** ключ (рекомендуется, чтобы не
смешивать лимиты прода с тестовым трафиком) — на прод-ключе можно оставить
только `avino.uz` / `*.avino.uz`, без `localhost`.

HTTP Геокодер (server-side) обычно не требует referrer-whitelist — он
ограничивается по самому ключу и/или IP в настройках кабинета, если такая
опция включена.

## 5. Шаг 3 — лимиты и биллинг (важно для прода, не для дева)

- Бесплатная квота у Yandex Maps API ограничена (порядок — тысячи запросов в
  день на продукт; точные цифры смотреть в кабинете на момент подключения,
  Yandex их периодически меняет).
- Для прод-трафика (реальные пользователи `/search`, `/map`, автосаджест на
  каждый ввод в поиске, геокодинг каждого создания/правки объявления)
  бесплатной квоты, скорее всего, не хватит после роста нагрузки — кабинет
  предложит привязать **биллинг-аккаунт Yandex Cloud** для оплаты сверх
  квоты.
- Это тоже Шаг 0 (владелец, не агент) — картой/реквизитами занимается Team
  Lead.
- Рекомендация: включить в кабинете **алерты по расходу/квоте**, если
  доступны — иначе превышение квоты в проде тихо превращается в `403` на
  карте и в геокодере (адрес просто не нормализуется, см. `AddressResolverService`
  — деградация без падения, но и без результата).

## 6. Шаг 4 — куда вписать ключ в этом репозитории

**Не коммитить сами значения.** Только через deploy-секреты / `.env` на
сервере, вне git (как и `SMTP_*`, см. `docs/GUIDE_YANDEX_SMTP_SETUP.md`).

- `apps/api` (server, secret) — `YANDEX_MAPS_API_KEY` в env контейнера `api`
  (`docker-compose.prod.yml` / prod `.env`). Рестарт `api` — без ребилда.
- `apps/client` и `apps/web` (browser) — `NEXT_PUBLIC_YANDEX_MAPS_API_KEY`
  (+ опционально `NEXT_PUBLIC_YANDEX_SUGGEST_API_KEY`) как **build-arg** при
  сборке Docker-образа прод-фронтов — значение печётся в бандл, смена требует
  **ребилда**, не только рестарта.
- Свериться с `docs/ENV.md` §10 и §17 — там уже задокументированы обе
  переменные и их client/server-статус.

## 7. Шаг 5 — live-verify (по аналогии с Eskiz/SMTP)

1. **HTTP Геокодер (server)**:
   ```bash
   curl "https://geocode-maps.yandex.ru/1.x/?apikey=<YANDEX_MAPS_API_KEY>&format=json&geocode=Ташкент,+улица+Амира+Темура+1"
   ```
   Ожидается `200` и JSON с `GeoObjectCollection.featureMember` — не `403`
   (ключ не активирован / нет квоты) и не `400` (невалидный ключ).
2. **JS API (browser)**: открыть прод `avino.uz/map` или `/search`, в
   DevTools Network убедиться, что запрос к `api-maps.yandex.ru` вернул `200`,
   карта отрисовалась (не заглушка-подсказка).
3. **Геосаджест**: на `/` (Hero) или `/search` (FilterBar) ввести адрес вне
   Ташкента (напр. «Наманган») — должны появиться подсказки за пределами
   захардкоженных районов Ташкента (ADR-0079 live-verify кейс).
4. **Геокодинг при создании объявления**: создать/отредактировать листинг с
   адресом — в БД `listings.address_en` и координаты должны заполниться (не
   остаться пустыми/сырыми), см. ADR-0147.

## 8. Troubleshooting

| Симптом | Причина / фикс |
|---|---|
| Карта показывает подсказку вместо карты | `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` пуст или не попал в билд — фронт деградирует, не падает (по дизайну, ADR-0073) |
| `Suggest is not available` в консоли | Ключ не подключён к продукту «API Геосаджеста» (ADR-0079) |
| `403` на `suggest-maps.yandex.ru` / `api-maps.yandex.ru`, выглядит как CORS | Домен не в HTTP-Referer whitelist ключа — добавить `avino.uz` / `*.avino.uz` |
| `403`/`400` на `geocode-maps.yandex.ru` | Ключ не активирован для HTTP Геокодера, либо превышена квота — проверить в кабинете |
| Поменяли `NEXT_PUBLIC_*`, а на сайте старое поведение | `NEXT_PUBLIC_*` печётся в билд — нужен ребилд Docker-образа, рестарта контейнера недостаточно |
| Адрес объявления не геокодится (координаты пустые) | `YANDEX_MAPS_API_KEY` не прокинут в env контейнера `api`, либо квота HTTP Геокодера исчерпана — `AddressResolverService` деградирует тихо (см. ADR-0147) |
