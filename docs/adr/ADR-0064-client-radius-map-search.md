# ADR-0064 — Радиусный гео-поиск на карте клиента (нарисовал круг → отфильтровал выдачу)

## Status

Accepted

## Date

2026-06-12

## Context

Нужен пространственный фильтр выдачи `/search` публичного портала: пользователь
рисует на карте круг, и список+пины показывают только объявления внутри него.

Бэкенд уже готов: `GET /api/v1/search/radius` (TASK-082, API.md §10) — PostGIS
`ST_DWithin` по GIST-индексу, наследует все фильтры §9 (тип сделки/недвижимости,
цена, комнаты, q, sort, limit), `radius_m` 1..50000, каждый элемент несёт
`distance_m`. На фронте карта — Leaflet (`MapView`, ADR/SPEC §2: при переезде на
Yandex Maps меняется только этот файл), фильтры живут в URL query
(единственный источник истины, см. `search/page.tsx` + `FilterBar`).

Сопутствующая проблема: у seed-данных не было координат (31 из 32 листингов с
`latitude/longitude = NULL`), из-за чего пины вообще не появлялись и фича
карта↔список выглядела сломанной.

## Decision

1. **Круг — в URL** (`?clat=&clng=&radius=`), как остальные фильтры. Страница
   (server component) парсит и валидирует параметры (`lib/geo.ts:
   parseCircleParams`, WGS84-диапазоны, радиус 1..50000 м; невалидные → молча
   обычный `/search`) и выбирает эндпоинт: `searchRadiusListings()` ↔
   `searchListings()` (общий `buildSearchParams`). Ссылка с радиусом шарится и
   переживает перезагрузку; back/forward работают из коробки.
2. **Рисование — свои pointer-события, без leaflet-draw.** Кнопка «Радиус»
   (оверлей на карте, `SearchResults`) включает draw-режим в `MapView`:
   drag карты выключается, `pointerdown` фиксирует центр, `pointermove`
   растит превью `L.Circle`, `pointerup` зажимает радиус в 250 м..50 км и
   отдаёт `onDrawComplete` → `router.replace` с новыми query-параметрами.
   Pointer events покрывают мышь и тач одним кодом.
3. **Активный круг** рендерится из URL-пропса поверх карты (стиль ink/8 %
   заливки, `interactive: false` — клики проходят к пинам), карта подгоняется
   под границы круга; авто-зум к пинам в это время отключён (иначе они
   конфликтуют). Чип «Радиус N км ✕» поверх карты сбрасывает фильтр.
4. **Seed-данные с координатами**: `seed-demo.cjs` задаёт реальные координаты
   районов Ташкента (повторный прогон обновляет существующие записи); прочие
   локальные записи добиты детерминированным разбросом по `md5(id)` вокруг
   центра города.

## Alternatives considered

- **leaflet-draw / @geoman-io** — лишняя зависимость ради одного жеста, чужая
  стилистика контролов, всё равно пришлось бы переписывать под брендовые пины.
- **Фильтрация на клиенте (haversine по загруженной странице)** — фильтрует
  только уже загруженные ≤24 элемента, ломает пагинацию/sort/счётчик; бэкенд с
  PostGIS уже умеет правильно.
- **Поиск по bounds видимой области (TASK-152, `/search/bounds`)** — другой UX
  («искать при движении карты»), не заменяет явный радиус; может быть добавлен
  отдельно, инфраструктура (URL-параметры, MapView-пропсы) переиспользуется.

## Consequences

- `MapView` получил три новых пропса (`circle`, `drawMode`, `onDrawComplete`);
  контракт стабилен для будущего переезда на Yandex Maps JS API.
- В выдаче с радиусом сортировка остаётся promotion-приоритетной (как `/search`);
  `distance_m` приходит с бэка, но в UI пока не показывается (можно добавить в
  карточку позже).
- `district`-фильтр по-прежнему не уходит на бэк (TODO(geo-reference), ADR-0062) —
  радиус частично закрывает этот пробел практичным способом.
- Live-проверка (Playwright, dev-стек): рисование мышью → URL
  `?clat=41.31263&clng=69.29230&radius=1147` → выдача 6 → 1 объявление, пины
  только внутри круга, чип «Радиус 1,1 км», сброс возвращает полную выдачу.
