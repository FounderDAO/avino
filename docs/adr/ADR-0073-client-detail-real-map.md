# ADR-0073 — Real Yandex map on listing detail (single pin + privacy radius)

## Status

Accepted

## Date

2026-06-15

## Context

На карточке объекта (`apps/client/src/features/detail/Detail.tsx`) блок
«На карте» был **декоративной CSS-сеткой** с пином по центру (фейк-карта), хотя
`/search` и `/map` уже используют настоящую карту Yandex через общий
`features/map/MapView.tsx` (ADR-0066). Это нарушало CLAUDE.md §12 (карты — только
Yandex Maps) и создавало UX-обман: пользователь видел «карту», которая не
показывала реальное местоположение объекта (UI/UX-аудит, TASK-196).

Ограничения:
- Работаем строго в `apps/client` (CLAUDE.md §0).
- `MapView` грузит Yandex JS API только в браузере (`window`), поэтому в выдаче
  он подключается через `next/dynamic` c `ssr:false` из **клиентской** обёртки
  (нельзя `ssr:false` из серверного `Detail.tsx`).
- Приватность: до контакта с автором нельзя выдавать точный адрес/здание
  (согласуется с ADR-0069 — телефон публичен, но «точное местоположение —
  по запросу»).

## Decision

1. **Переиспользуем общий `MapView`** (тот же, что на `/search` и `/map`) —
   никаких изменений в самом `MapView`. Новая клиентская обёртка
   `features/detail/DetailMap.tsx` (`'use client'`) делает `next/dynamic`
   `ssr:false` и подаёт `MapView` ровно **один листинг** → один ценовой пин по
   координатам объекта, `autoFit={false}`, центр и зум — по объекту.

2. **Приватность через радиус-круг.** `DetailMap` передаёт `circle`
   (`RadiusCircle`, `APPROX_RADIUS_M = 500 м`) вокруг точки; overlay-эффект
   `MapView` кадрирует вид по кругу (`setBounds`), поэтому показывается
   приблизительная зона района, а не конкретное здание.

3. **Fallback без координат.** Если у объекта нет `lat/lng`, `DetailMap` не
   рендерится, а `Detail.tsx` показывает аккуратную плашку с иконкой и текстом
   `listing.map.note` («точное местоположение — по запросу») — без клетчатой
   заглушки.

4. **Деградация без ключа** наследуется от `MapView`: без
   `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` карта показывает подсказку, страница не
   падает.

Ключ i18n `listing.map.pin` больше не используется (оставлен в каталогах как
безвредный, удаление — отдельная рутинная задача при чистке мёртвых ключей).

## Consequences

Positive:
- Карточка объекта показывает настоящую карту Yandex — единый картовый слой
  во всём публичном портале, конец UX-обмана (§12 соблюдён).
- Нулевой риск регрессий на `/search` и `/map`: `MapView` не тронут, вся новая
  логика — в изолированной обёртке `DetailMap`.
- Приватность сохранена: приблизительная зона вместо точного адреса.

Negative / trade-offs:
- На детальной карте пин — **ценовой пилюль** (как в выдаче), а не нейтральный
  маркер. Это осознанный компромисс ради полного переиспользования `MapView`;
  при желании позже можно добавить `singlePin`-режим в `MapView`.
- Точность зоны фиксирована (500 м) и не зависит от типа объекта.
- Карта — только клиент (CSR-остров внутри серверной карточки), как и в выдаче.
