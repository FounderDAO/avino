# ADR-0074 — Витрина без фото-пустышек: фото-приоритет + локальный плейсхолдер

## Status

Accepted

## Date

2026-06-15

## Context

На сиде у большинства листингов нет медиа. До этого клиентский слой
(`apps/client/src/lib/api/listings.ts`) подставлял каждому листингу без фото
внешний URL `https://placehold.co/...?text=Avino`. Последствия:

- Главная («Рекомендуем», «Свежее в аренде») и блок «Похожие» на карточке были
  забиты серыми плашками-пустышками → витрина выглядела «пустой» и подрывала
  доверие (UI/UX-разбор против Zillow, TASK-197).
- Внешний хотлинк на `placehold.co` — лишняя сетевая зависимость и приватность
  (запрос к стороннему домену на каждой карточке без фото).
- `PhotoImg` уже умел рисовать аккуратный дом-глиф, но только по `onError`;
  для `placehold.co` загрузка проходила успешно, поэтому красивый плейсхолдер
  никогда не показывался.

## Decision

Решение реализуется ТОЛЬКО в `apps/client` (граница app-папок, CLAUDE.md §0):

1. **Нет фото → пустой `photos: []`.** `toPhotos` больше не подставляет внешний
   URL. Признак «есть фото» = `listing.photos.length > 0`.
2. **Фото-приоритет витрины.** Чистая функция `prioritizePhotos(listings)` —
   стабильная партиция: листинги с фото первыми, без фото в конце (промо-порядок
   внутри групп сохраняется). Применяется в `getFeaturedListings`
   («Рекомендуем»), на главной для «Свежее в аренде» и в `getSimilarListings`
   («Похожие»). Селекторы витрины делают над-выборку (`limit×4`, ≤100 — лимит
   API §9), чтобы листинги с фото поднимались из «хвоста» промо-выдачи в срез.
3. **Локальный брендовый плейсхолдер.** `PhotoImg` рисует дом-глиф + бренд
   «Avino» на фоне `photo-ph` для пустого `src` (а не только по `onError`) —
   без внешнего хотлинка. `Gallery` на карточке объекта показывает тот же
   плейсхолдер вместо пустоты при `photos.length === 0`.

Полное исключение листингов без фото НЕ выбрано: на сиде это опустошило бы
витрину. Выбран мягкий вариант («задвигать в конец») из acceptance-критериев.

## Consequences

Positive:
- Витрина и «Похожие» наполняются листингами с реальными фото в первую очередь.
- Нет внешних запросов к `placehold.co`; плейсхолдер осмысленный и брендовый.
- `prioritizePhotos` — чистая, протестированная, переиспользуемая функция.

Negative / trade-offs:
- Над-выборка увеличивает размер ответа `/search` для витринных секций
  (ограничено ≤100). Фильтрация/срез — на клиенте.
- Фото-приоритет может опустить промо-листинг без фото ниже NORMAL с фото в
  витринных секциях (намеренно; платные VIP/TOP практически всегда с фото).
- Дедуп фото-приоритета по `photos.length` — клиентский признак; серверного
  поля «есть медиа» в выдаче `/search` нет (используем `thumbnail_url`).
