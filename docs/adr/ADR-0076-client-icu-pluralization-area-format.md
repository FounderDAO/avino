# ADR-0076 — ICU-плюрализация счётных единиц + чистое форматирование площади (apps/client)

## Status

Accepted

## Date

2026-06-15

## Context

Хелперы форматирования `apps/client/src/lib/format.ts` отдавали счётные единицы
через простую подстановку числа в строку словаря:

- `units.rooms = "{count}-комн."`, `units.roomsShort = "{count} комн"` — нет
  согласования по числу. В детальной карточке (`Facts.tsx`) комнаты вообще
  рендерились сырым числом под лейблом `Комнат` → визуально «1 Комнат» (нет
  RU-плюрализации: должно быть «1 комната / 2 комнаты / 5 комнат»).
- `units.area = "{value} м²"` — значение площади подставлялось как есть, поэтому
  данные вида `"60.00"` давали «60.00 м²» (лишние хвостовые нули).

next-intl уже использует ICU MessageFormat (см. `search.results.count`,
`search.map.areaCount`), но единицы в неймспейсе `units` его не задействовали.

## Decision

Включить ICU-плюрализацию для счётных единиц и нормализовать числовые значения
до подстановки — на уровне словаря `units` и хелперов `format.ts`, без правок в
самих компонентах сверх минимума.

- **Комнаты — ICU plural** в `messages/{ru,uz,en}.json`:
  - `units.rooms` (полная форма) и `units.roomsShort` (компактная) переведены в
    `{count, plural, …}`. RU — формы `one/few/many/other` («комната/комнаты/
    комнат»), UZ — единственная форма `other` (нет грамматического множественного),
    EN — `one/other`.
  - Добавлен `units.roomsLabel` — ICU-склонение **существительного без числа**
    («комната/комнаты/комнат»). `Facts.tsx` использует его как лейбл, а число —
    как значение карточки (паттерн «значение + категория», как у «Год постройки»),
    чтобы не дублировать корень слова («1» + «комната» вместо «1 комната» +
    «Комнат»).
- **Площадь без хвостовых нулей**: хелпер `normalizeArea()` (`Number(area)` →
  `toFixed(2)` → `parseFloat` → строка) применяется в `formatArea` и `specs()`
  до подстановки в `units.area`. `"60.00" → "60 м²"`, `"60.50" → "60.5 м²"`,
  `78 → "78 м²"`, `undefined/"" → ""`.
- **Юнит-тесты** `format.test.ts` строят настоящий next-intl translator
  (`createTranslator`, locale `ru`, messages из `ru.json`), чтобы ICU plural
  реально вычислялся; покрыты 1/2/5/0 комнат и дробная/целая/пустая площадь.

## Consequences

Positive:
- Корректные RU/UZ/EN-формы для комнат и любых будущих счётных единиц через ICU.
- Площадь больше не показывает «60.00 м²».
- Изменения локализованы в словаре + хелперах → все потребители (`PropertyCard`
  через `specs()`, `Facts`) получают исправление автоматически.

Negative / trade-offs:
- Строки `units.rooms*` стали ICU-выражениями: тесты, использующие наивную
  regex-подстановку вместо next-intl, не вычислят plural (поэтому тест построен
  на реальном translator).
- `formatRooms` остаётся экспортируемым хелпером, но в приложении напрямую больше
  не вызывается (используется в тестах и доступен для повторного использования).
