# ADR-0079 — Yandex Geosuggest по всему Узбекистану (apps/client)

## Status

Accepted

## Date

2026-06-15

## Context

Hero главной (`apps/client/src/features/home/Hero.tsx`) и `/search`
(`FilterBar.tsx`) используют общий хук `useGeoSuggest`, который мёржит локальные
районы Ташкента (мгновенно, структурный `?district_id=`) и адреса из Yandex
`ymaps.suggest`. На практике Yandex-подсказки **не приходили** — типичный экран:
ввод «Наманган» → «Ничего не найдено». Две причины:

1. **Загрузчик не передавал ключ саджеста.** `useYmaps.loadYmaps` грузил JS API
   только с `apikey`, тогда как Yandex JS API 2.1 требует **отдельный параметр
   `suggest_apikey`** для `ymaps.suggest`; без него SDK кидает
   `Suggest is not available`
   (docs: yandex.ru/dev/jsapi-v2-1 → dg/concepts/geocoding/suggest).
2. **Scope был захардкожен Ташкентом.** Запрос саджеста формировался как
   `ymaps.suggest("Ташкент, " + query)` — поэтому даже с рабочим саджестом всё
   вне Ташкента не находилось.

Требование Team Lead: поиск должен покрывать **весь Узбекистан** (города и
регионы, не только Ташкент).

## Decision

Browser-direct подход через `ymaps.suggest` (без бэкенд-прокси), две точечные
правки в `apps/client`:

- **`useYmaps.ts`** — в URL загрузчика добавлен `&suggest_apikey=…`.
  Значение по умолчанию = основной `NEXT_PUBLIC_YANDEX_MAPS_API_KEY`
  (`SUGGEST_API_KEY = process.env.NEXT_PUBLIC_YANDEX_SUGGEST_API_KEY || API_KEY`):
  достаточно **одного** ключа, если в Кабинете Yandex он подключён и к
  «JavaScript API», и к «API Геосаджеста». Отдельный ключ саджеста (если Yandex
  выдал его отдельно) задаётся через `NEXT_PUBLIC_YANDEX_SUGGEST_API_KEY`.
- **`useGeoSuggest.ts`** — scope расширен с города на страну: префикс запроса
  `"Ташкент, "` → `"Узбекистан, "` (константа `SUGGEST_SCOPE`). Районы Ташкента
  остаются сверху как мгновенный структурный слой; Yandex добавляет остальную
  страну.

Условие работоспособности (конфиг ключа, не код): домен(ы) сайта должны быть в
**HTTP-Referer вайтлисте** ключа в Кабинете Yandex (`avino.uz`, `*.avino.uz`;
`localhost` для дева). Без вайтлиста endpoint `suggest-maps.yandex.ru/v1/suggest`
отвечает `403`, что в браузере выглядит как CORS-ошибка (у 403 нет CORS-заголовков).

Проверено live (headless Chrome): ввод «Наманган» → «Наманганская область»,
«Наманган», «Чуст…», «Учкурган…», «Туракурган…». Прямой `ymaps.suggest` —
`200`, count=5.

## Consequences

Positive:
- Гео-подсказки по всему Узбекистану (города/районы/улицы); районы Ташкента
  по-прежнему сверху со структурным `?district_id=`.
- Один ключ обслуживает карту + геокодер + саджест; деградация без ключа/сервиса
  не сломана (фолбэк — только районы, без исключений).
- Минимальная правка (2 файла), без изменений бэкенда.

Negative / trade-offs:
- Каждый новый домен нужно добавлять в referer-вайтлист ключа Yandex.
  Альтернатива (рассмотрена, **не выбрана** для MVP): бэкенд-прокси
  `GET /api/v1/geo/suggest` — вайтлист одного домена, работает с любого origin
  (включая localhost), ключ уходит с фронта на сервер. Можно ввести позже.
- Выбор не-ташкентского города уходит в `?q=` (ILIKE по `address`), а не в
  структурный гео-фильтр → выдача пуста, пока в этих городах нет объявлений.
  Структурная гео-иерархия (таблицы регионов/городов) — отдельная задача.
- `NEXT_PUBLIC_*` ключ инлайнится в браузерный бандл (публичен по природе) —
  защита через referer-вайтлист, а не секретность.
