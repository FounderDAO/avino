# ADR-0080 — Адрес объявления: реальная Yandex-карта + Suggest-пикер (apps/client)

## Status

Accepted

## Date

2026-06-15

## Context

Шаг «Адрес» визарда создания объявления (`apps/client/src/features/listing-new`,
шаг 2 из 8) был **заглушкой**: текстовый инпут адреса без подсказок и
псевдо-«карта» (`PickMap`) — стилизованный `<div>` с сеткой улиц, который
проецировал пиксель клика в фейковые координаты вокруг центра Ташкента. Реальной
карты и геокодинга не было; владелец не мог ни найти свой адрес, ни поставить
честную точку.

CLAUDE.md §12 (Maps rules) прямо требует «выбор точки на карте при создании
объявления» на Yandex Maps. Вся инфраструктура уже есть в `apps/client` и
переиспользуется: загрузчик SDK `useYmaps` (с `suggest_apikey`, ADR-0079),
автокомплит `SearchAutocomplete` + `useGeoSuggest` (Yandex Suggest по всему
Узбекистану, ADR-0079), типы/хелперы `lib/geo`.

## Decision

Browser-direct (без бэкенд-прокси), в пределах `apps/client`:

- **`features/map/geocode.ts`** (новый) — точечный геокодинг через
  `loadYmaps().geocode`: `geocodeToPoint` (адрес → `[lat, lng]` +
  нормализованный адрес) и `reverseGeocode` (точка → адрес). Любая осечка → `null`
  (без исключений). Отличие от `resolveSuggestion` (search): тот даёт bbox→circle
  для радиус-поиска, здесь нужна одна точка.
- **`PickMap.tsx`** (переписан) — реальный `ymaps.Map` с одной перетаскиваемой
  меткой (`preset islands#redIcon`). Клик по карте ставит/двигает точку,
  перетаскивание уточняет; каждое изменение эмитит координаты и обратно геокодит
  точку → строку адреса. Внешнее изменение точки (выбор подсказки → геокод)
  центрирует карту и двигает метку. Деградация (нет ключа / SDK упал) → подсказка
  вместо карты, шаг не падает.
- **`AddressStep.tsx`** (новый) — инкапсулирует автокомплит + карту +
  двустороннюю синхронизацию. Переиспользует `SearchAutocomplete` + `useGeoSuggest`
  (районы Ташкента отключены пустым списком — адрес объекта точный, не «район»).
  Выбор подсказки / Enter → геокод адреса → точка + центрирование; клик/drag
  метки → обратный геокод → адрес.
- **`ListingNew.tsx`** — шаг 2 заменён на `<AddressStep>`, добавлен `useLocale()`.

**Изменение валидации шага 2:** теперь обязателен только текст адреса; точка на
карте — необязательное уточнение. Так сбой Yandex (ключ/квота/реферер) не может
полностью заблокировать создание объявления. На счастливом пути координаты всё
равно проставляются автоматически при выборе адреса, а `buildBody` и раньше слал
`latitude`/`longitude` условно (`if (f.coords)`), так что контракт API не меняется.

Условие работоспособности (конфиг ключа, не код) то же, что в ADR-0079: домен в
HTTP-Referer вайтлисте ключа Yandex; SDK с `suggest_apikey`.

## Consequences

Positive:
- Владелец находит адрес автоподсказкой по всему Узбекистану и ставит/уточняет
  честную точку на реальной карте; адрес и точка синхронизированы в обе стороны.
- Полное переиспользование существующей Yandex-инфраструктуры (`useYmaps`,
  `useGeoSuggest`, `SearchAutocomplete`, `lib/geo`) — без дублирования.
- Сбой/отсутствие карты не блокирует публикацию (адрес можно ввести текстом).

Negative / trade-offs:
- Перетаскивание/клик по карте перетирают текст адреса результатом обратного
  геокода — точные детали (кв., подъезд) пользователь дописывает вручную после.
- Реальная карта добавляет зависимость от Yandex JS API на шаге адреса (раньше
  заглушка работала всегда). Митигировано опциональностью координат + фолбэком.
- `NEXT_PUBLIC_*` ключ публичен по природе (инлайнится в бандл) — защита через
  referer-вайтлист, не секретность (как и в ADR-0079).
