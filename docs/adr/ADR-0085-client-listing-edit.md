# ADR-0085 — Редактирование объявления + точечные фиксы кабинета (apps/client)

## Status

Accepted

## Date

2026-06-18

## Context

Пользователь сообщил о четырёх дефектах публичного портала (`apps/client`):

1. **Редактирование объявления не работало.** Кнопка «Редактировать» в
   «Мои объявления» (`features/account/MyListings.tsx`) вела на `/sell/new` —
   пустой визард создания, без id и без предзаполнения. Маршрута `/sell/[id]/edit`,
   клиентских эндпоинтов GET/PATCH `/listings/:id` и режима редактирования у
   формы не существовало — хотя бэкенд их полностью поддерживает (GET/PATCH
   `/listings/:id`, media GET/POST/DELETE/reorder).
2. **«Отмена» уводила на лендинг** `/sell` (захардкоженный `Link href="/sell"`),
   а не туда, откуда пользователь пришёл.
3. **Карточка пользователя в кабинете была статичной** —
   `features/account/AccountLayout.tsx` рендерил захардкоженные «Алишер /
   +998 90 •• 67» без обращения к Redux (в коде стоял комментарий «всё —
   мок-данные»). `Header.tsx` и `Profile.tsx` уже брали данные правильно из
   `selectCurrentUser`.
4. **На форме создания не работали гео-подсказки и карта.** Это оказался **не
   дефект кода**: запущенный Docker-образ `avino-client` был собран до коммита
   `e3a7d91` («real Yandex map + address suggest on listing step 2»), т.е. крутил
   старый бандл с plain-инпутом адреса. Код на диске уже корректен; проблема —
   протухший образ (см. [memory] и ADR-0079/0080). Фикс — пересборка образа, без
   изменений кода. Здесь не фиксируется кодом, отмечен для контекста.

ADR покрывает решения по пунктам 1–3 (изменения кода).

## Decision

Всё в пределах `apps/client`, browser-direct через существующий RTK Query
(`baseApi`), без новых бэкенд-ручек.

### 1. Редактирование — отдельная одностраничная форма

- **`store/api/listingEditApi.ts`** (новый) — `getListingForEdit` (GET
  `/listings/:id`, Bearer → владелец видит и свои non-ACTIVE), `updateListing`
  (PATCH `/listings/:id`, тело строго по `UpdateListingDto`, snake_case,
  `translation` вложен), `addListingMedia`/`deleteListingMedia`/
  `reorderListingMedia`. Инвалидация: `{ type:'Listing', id }` + общий тег
  `'Listing'` → списки (`myListings`) обновляются.
- **`features/listing-edit/ListingEdit.tsx`** (новый) — все поля на одной
  странице (удобнее точечной правки, чем 8-шаговый визард). **Переиспользует**
  `AddressStep` (Yandex suggest + карта) и `PhotoUploader` — нулевой риск
  расхождения с формой создания, что и было жалобой «форма не подходит».
  Существующие фото = `UploadPhoto` без `file` (id = mediaId), новые — с `file`.
  Сохранение транзакционно по шагам: PATCH полей → удалить снятые фото →
  загрузить новые (получить их id) → выставить итоговый `reorder`. Сбой одной
  медиа-операции не валит всё сохранение (degrade, не throw).
- **`app/[locale]/sell/[id]/edit/page.tsx`** (новый) — тонкая серверная обёртка
  (метаданные) + клиентский `ListingEdit`, который сам грузит объявление по id.
- `MyListings.tsx` — «Редактировать» → `/sell/:id/edit`.

**Почему single-page, а не переиспользование визарда:** правка обычно точечная
(цена/описание), прокликивать 8 шагов — плохой UX. Консистентность полей
обеспечивается переиспользованием `AddressStep`/`PhotoUploader`, а не общей
оболочкой.

**Границы (v1):** `original_language` менять нельзя (ADR-005) — язык оригинала
показан read-only; сейчас перевод у объявления один, поэтому GET всегда отдаёт
оригинал → префилл безопасен, PATCH пишет в ту же (оригинальную) запись.
Ре-модерация после правки ACTIVE — задача M5 (статус не трогаем). Сохранение
требует ≥1 фото (как и создание).

### 2. «Отмена»

`ListingNew` — кнопка «Отмена» теперь `router.back()` (возврат туда, откуда
пришли). В `ListingEdit` отмена ведёт к «Моим объявлениям» (точка входа в
редактирование).

### 3. Карточка пользователя в кабинете

`AccountLayout` берёт `selectCurrentUser` (тот же источник, что `Header`):
`display_name → first_name → phone → «Гость»`; телефон скрыт у гостя. Захардкод
удалён.

i18n: namespace `listingEdit.*` + `account.userCard.guest` в RU/UZ/EN.

## Consequences

- Владелец может реально редактировать объявление (поля + полное управление
  фото) и сохранять без расхождений с формой создания.
- «Отмена» больше не выбрасывает на лендинг; кабинет показывает настоящего юзера.
- Edit использует уже существующие, проверенные бэкенд-эндпоинты — без расширения
  API. Будущая ре-генерация переводов/ре-модерация после правки — отдельная M5.

## Verification

Пересобран образ `avino-client`, поднят на :3001. Live (Chrome DevTools Protocol):

- Создание: ввод адреса → 7 Yandex-подсказок → выбор → карта встала в точку
  (`41.36615, 69.28856`) — пункт 4 подтверждён после пересборки.
- Кабинет: захардкод «Алишер/+998 90 •• 67» исчез; гость → «Гость».
- Редактирование (OTP-логин → создать объявление+фото → `/sell/:id/edit`):
  все поля предзаполнены; правка заголовка → Save → редирект на «Мои
  объявления»; GET `/listings/:id` подтвердил сохранённый заголовок.
- `tsc --noEmit`, `next lint`, Docker `next build` — зелёные.
