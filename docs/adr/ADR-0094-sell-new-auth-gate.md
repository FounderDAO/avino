# ADR-0094 — Гейт авторизации на `/sell/new` (модалка входа для гостей)

## Status
Accepted

## Date
2026-06-19

## Context
Страница визарда «Разместить объявление» (`/sell/new`, `ListingNew.tsx`) была
доступна гостю целиком: форму можно было заполнить от начала до конца, и только на
финальном шаге «Опубликовать» гость упирался в `errors.loginRequired` (а на превью
показывался `errors.guestHint`). То есть пользователь тратил время на 8 шагов
визарда и узнавал о необходимости входа в самом конце — плохой UX и лишняя работа
вхолостую.

Требование Team Lead: при открытии `/sell/new` неавторизованным пользователем
сразу показывать модалку входа.

В проекте уже есть переиспользуемый `LoginModal` (OTP телефон/email + Google,
`components/layout/LoginModal.tsx`, рендерится через Radix `Dialog.Portal`) и
селектор `selectIsAuthenticated` (`store/slices/authSlice.ts`). Приватные страницы
кабинета (`MyListings`, `ListingEdit`) уже гейтятся через прямую ветку по
`isAuthenticated` с экраном-заглушкой.

## Decision
Гейтить `/sell/new` целиком: визард рендерится только авторизованному
пользователю. Для гостя — ранний `return` с экраном-заглушкой (иконка `Lock`,
заголовок/текст, кнопки «Войти» и «На главную») и **автоматически открытой**
`LoginModal`.

Ключевые решения реализации:
- Авто-открытие модалки делается **через `useEffect` (после монтирования)**, а не
  в начальном стейте: на сервере и при первом клиентском рендере store ещё не
  гидрирован токеном из localStorage, поэтому открытие модалки в SSR/гидрации
  вызвало бы мелькание у уже залогиненных пользователей. Эффект выполняется только
  на клиенте → у гостя модалка открывается, у авторизованного — нет.
- Решение «гость закрыл модалку» vs «гость успешно вошёл» **не зависит от тайминга
  router/redux**: ветка определяется только текущим `isAuthenticated`. Гость,
  закрывший модалку, остаётся на экране-заглушке с кнопкой «Войти» (переоткрыть);
  после успешного входа `isAuthenticated → true` → рендерится визард. Гонок нет.
- Новый i18n-блок `listingNew.auth` (`title`, `text`, `context`, `login`, `home`)
  в ru/uz/en. `context` передаётся в `LoginModal` как подпись-причина входа.

Прежние гостевые проверки в визарде (`handlePublish` → `loginRequired`, превью →
`guestHint`) оставлены как defense-in-depth (теперь недостижимы для гостя, но
безопасны при истечении токена в середине сессии — ветка гейта перехватит ре-рендер).

## Consequences
Положительно:
- Гость узнаёт о необходимости входа сразу, а не после 8 шагов; меньше работы
  вхолостую.
- Переиспользует существующий `LoginModal` (единый OTP/Google-флоу) и паттерн
  гейтинга приватных страниц — без новых зависимостей и без правок бэкенда.
- Гейт race-free: исход зависит только от состояния авторизации.

Компромиссы / trade-offs:
- Как и у других гейт-страниц (`MyListings`, `ListingEdit`), SSR всегда отдаёт
  экран-заглушку (на сервере нет localStorage → `isAuthenticated=false`); у уже
  авторизованного пользователя возможна краткая вспышка заглушки до гидрации.
  Принято ради консистентности с существующим паттерном; модалка при этом НЕ
  мелькает (контролируется эффектом).
- Гость больше не может «пощупать» форму без входа. Это и есть желаемое поведение
  (требование Team Lead), но это смена продуктового поведения, а не чистый багфикс.
