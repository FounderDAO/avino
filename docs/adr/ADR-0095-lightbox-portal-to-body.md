# ADR-0095 — Лайтбокс фото: portal в `body` (фикс «слишком длинной» модалки)

## Status
Accepted

## Date
2026-06-19

## Context
При открытии фото из карточки объявления (`/listing/:id`) полноэкранный лайтбокс
(`components/ui/lightbox.tsx`, `fixed inset-0`) растягивался на **всю высоту
страницы (~1600px)**, а не на вьюпорт (≈900px): тёмный фон не закрывал экран,
фото оказывалось у галереи, стрелки «prev/next» — у низа страницы, счётчик не по
центру. Пользователь сообщил: «modal слишком длинный».

Причина — классическая ловушка `position: fixed`. Обёртка detail-страницы носит
глобальный класс `.fade-up` (`globals.css`): `animation: avino-fade-up .35s ease
both`. Кадры анимации трогают `transform`, а `animation-fill-mode: both`
оставляет элемент в forwards-fill-состоянии и после завершения — Chrome продолжает
считать такой элемент **containing block для `position: fixed`-потомков**. В
результате `fixed inset-0` лайтбокса отсчитывался от трансформированного предка
(высокого контента страницы), а не от вьюпорта.

`LoginModal` тем же багом не задет, потому что рендерится через Radix
`Dialog.Portal` (в `body`).

## Decision
Рендерить лайтбокс через `createPortal(jsx, document.body)`, чтобы оверлей
выносился из-под `.fade-up`-предка и `fixed inset-0` снова отсчитывался от
вьюпорта. Дополнительно:
- **Блокировка прокрутки фона** (`document.body.style.overflow = 'hidden'`) пока
  лайтбокс открыт, с восстановлением прежнего значения на размонтировании.
- **SSR-guard** `typeof document === 'undefined'` перед порталом (лайтбокс и так
  открывается только на клиенте по клику, но guard делает компонент безопасным при
  любом серверном проходе).
- **`min-h/min-w-[280px]` на медиа**: битое/отсутствующее фото (в dev demo-сиды
  отдают R2 `NoSuchKey`) показывается осмысленной брендовой карточкой, а не
  крошечным глифом. Для реальных фото пол ниже типичного fit-размера и не влияет
  (прозрачные поля над чёрным оверлеем не видны).

**Правило на будущее:** любой новый полноэкранный `fixed`-оверлей в `apps/client`
должен порталиться в `body` — нельзя полагаться на `fixed inset-0` внутри контента
страницы, пока в дереве есть `.fade-up`/любой `transform`/`filter`/`contain`-предок.

## Consequences
Положительно:
- Лайтбокс — корректная центрированная полноэкранная модалка: оверлей закрывает
  вьюпорт, фото/стрелки/счётчик центрированы. Проверено headless-Chrome: rect
  диалога 1602×1280 → 900×1440 (= вьюпорт).
- Фон не скроллится под открытой модалкой.
- Battle-tested подход (тот же, что у Radix `Dialog.Portal`).

Компромиссы / trade-offs:
- Появилась зависимость от `document` (через `createPortal`) — закрыта SSR-guard'ом
  и тем, что компонент монтируется только на клиенте.
- `min-*` на медиа — компромисс ради демо/битых картинок; на проде с реальными
  фото не виден.
