# ADR-0142 — Access-токен публичного портала только в памяти

## Status

Accepted

## Date

2026-07-13

## Context

Security-аудит аутентификации (2026-07-13, см. ADR-0141) отметил асимметрию:
админка (apps/web, ADMIN-04) держит access-токен только в памяти Redux, а
публичный портал (apps/client, TASK-150) зеркалил в localStorage **оба** токена.
localStorage читается любым JS на странице — XSS или компрометация стороннего
скрипта уносили и 15-минутный access, и 30-дневный refresh.

Это PR-2 плана hardening (quick wins). Целевое состояние (BFF + httpOnly
cookies) — отдельные PR.

## Decision

1. **Access — только в памяти Redux** (паритет с админкой). В localStorage
   остаётся один refresh (`avino.client.refresh_token`).
2. **Восстановление после перезагрузки/смены локали** — существующим флоу без
   изменений: authSlice гидрирует refresh → SessionBootstrap дёргает
   `GET /auth/me` → 401 → baseQueryWithReauth ротирует пару (single-flight) →
   access в памяти, повтор запроса. useRealtimeBridge подключает сокет,
   когда access появляется в store.
3. **Миграция**: `buildInitialState()` при создании store вычищает легаси-ключ
   `avino.client.access_token`, записанный кодом до этого ADR. Разлогина нет —
   refresh остаётся валидным.
4. **Refresh для ротации читается из localStorage** (`readPersistedRefreshToken`,
   фолбэк — Redux). localStorage общий для вкладок: после ротации в соседней
   вкладке Redux-снапшот текущей протухает, а повторная ротация протухшим
   токеном = `TOKEN_REUSED` → отзыв всей session family (docs/API.md §3) →
   разлогин всех вкладок. Частота ротаций с этим ADR растёт (каждая
   перезагрузка), поэтому фикс обязателен.

## Consequences

- XSS больше не может украсть access из storage; окно атаки сузилось до
  чтения Redux-состояния работающей вкладки (что требует исполнения кода в
  контексте страницы и не переживает её закрытие). Refresh в localStorage
  остаётся главным риском — его закрывает будущий BFF-этап.
- +1 запрос `/auth/refresh` на холодную загрузку залогиненного пользователя
  (и на смену локали — store пересоздаётся, ADR у #386). Це́на приемлемая:
  ротация атомарна и single-flight.
- Кросс-вкладочные гонки ротации сведены к минимуму, но полностью исключит их
  только BroadcastChannel/BFF — вне скоупа.

## Verification

- 531 тест client зелёный, включая новые: access не персистится и не
  переживает пересоздание store; легаси-ключ вычищается.
- Live: браузер со старой сессией (оба токена в LS от прежнего кода) →
  новый билд: легаси-ключ удалён, в LS только refresh, сеть показывает
  `/auth/me` 401 → `/auth/refresh` 200 → `/auth/me` 200, топбар залогинен.
