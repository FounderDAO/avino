# ADR-0147 — Нормализация адреса объявления + ru/en геокодинг по координатам

## Status

Accepted

## Date

2026-07-13

## Context

`listings.address` заполнялся сырой строкой из трёх независимых источников и
ломал вёрстку карточек/детали:

- Yandex Suggest в визарде (`AddressStep.handleSelect`) сохранял `displayName`
  как есть: «город Ташкент, Мирзо-Улугбек, ул. Бабура, 13, Мирзо-Улугбек р-н,
  Ташкент» — с дублями района/города в хвосте;
- реверс-геокод при перетаскивании точки (`geocode.ts getAddressLine()`)
  возвращал «Узбекистан, Ташкент, …» — с страной в начале;
- сиды (`seed-all.cjs`) собирали адрес с префиксом «город » из `regions.name_ru`.

Плюс адрес хранился только на русском: переключение локали en/uz на карточке
и в детали ничего не меняло.

## Decision

1. **Формат** — единая чистая функция `formatAddress` (apps/api/src/geo/address-format.ts):
   `{locality}, {district}, {street}, {house}`, без страны, без «город »-префикса,
   без дублей района/города в хвосте. Сокращения для ru-улиц: «улица »→«ул. »,
   «проспект »→«просп. », «переулок »→«пер. », «бульвар »→«бул. », «площадь »→«пл. »
   (en не трогаем — латиница из геокодера уже короткая).
2. **Серверный реверс-геокод** — `AddressResolverService` (apps/api/src/geo/):
   на вход `lat`/`lng`/`districtId?`, два параллельных запроса к Yandex HTTP
   Геокодеру (`https://geocode-maps.yandex.ru/1.x/`, `kind=house`, `results=1`,
   `lang=ru_RU` и `lang=en_US`, таймаут 3s каждый). Ключ — тот же
   `YANDEX_MAPS_API_KEY`, что уже используется для JS Maps API; entitlement
   на HTTP Геокодер проверен curl'ом 2026-07-13 (оба языка вернули 200 и
   полные структурные компоненты).
   - Парсятся **только структурные** `Address.Components` (`locality`,
     `street`, `house` по `kind`) — строка `text` из ответа не режется.
   - Район в оба языка подставляется НЕ из ответа геокодера, а из **нашей**
     таблицы `districts` по `district_id` (`DistrictsService.namesByIds` +
     `pickName`) — консистентно с тем, как район показывается по всему сайту
     (фильтры, `district_name` в выдаче). Нет `district_id` → компонент района
     просто опускается из строки.
   - Best-effort: нет ключа / сеть / таймаут / пустой ответ на ru → весь резолв
     возвращает `null`, вызывающий (`ListingsService`) уходит в строковый
     фолбэк. Создание/правка объявления никогда не блокируется геокодером.
   - `uz` не запрашивается — Yandex Геокодер узбекский не поддерживает
     (подтверждено в спеке); en-версия для uz-локали не отображается, клиент
     показывает ru как фолбэк (реализация клиента — вне этого PR).
3. **Строковый фолбэк** — чистая функция `normalizeAddress(raw: string)`:
   сплит по `, `, выброс частей-стран (`узбекистан`/`uzbekistan`/`o'zbekiston`
   и написания), срез префиксов «город »/«г. », срез частей-дублей (сравнение
   по нормализованному ключу: lower, ё→е, без хвостов « р-н»/« район»/
   « district», без суффикса «ский»). Идемпотентна. Применяется всегда, когда
   в `dto.address` пришла строка и геокодер не вернул результат — даже если
   ключ задан, но сеть/апстрим недоступны.
4. **Хранение en-версии — `listings.address_en`, НЕ `listing_translations`.**
   `ListingTranslation.title`/`.source` `NOT NULL`, а строка перевода создаётся
   только на модерации (автопереводчиком/вручную) — upsert «только адрес» при
   создании объявления потребовал бы фиктивный `title` и ломал бы семантику
   `is_auto_translated`/полноты переводов (ADR-0091). Адрес — машинно
   выводимая гео-строка, а не пользовательский текстовый перевод, поэтому живёт
   в `listings` рядом с `address` (миграция `20260713060000_add_listing_address_en`).
5. **Хук в `ListingsService.applyAddress`** (create + update):
   - если в dto пришли `latitude`+`longitude` (обе) — синхронный best-effort
     резолв через `AddressResolverService`; успех → `address`/`address_en`
     перезаписываются результатом геокодера, райт-адрес пользователя из
     `dto.address` в этом случае игнорируется;
   - геокодер не дал результата **и** в dto пришёл `address` — `address =
     normalizeAddress(dto.address)`, `address_en = null` (протухшая en-версия
     сознательно сбрасывается, т.к. могла относиться к старым координатам);
   - **residual-риск**: если `update` прислал только новые координаты (без
     `address` в dto) и геокодер в этот момент недоступен — ни один из
     блоков не выполняется, `address`/`address_en` в БД остаются от старых
     координат (устаревшими). Принято осознанно: визард всегда шлёт
     `address`+`latitude`+`longitude` одной парой, отдельного UI «двигаю
     точку без текста» в клиенте нет; риск открыт для будущих клиентов
     (мобилка), которые могут слать координаты без адреса.
6. **Backfill** (`apps/api/src/scripts/backfill-addresses.ts`, one-off,
   запускается вручную `node dist/scripts/backfill-addresses.js`): все
   не-`DELETED` объявления — с координатами → резолв геокодером (пауза 300ms
   между запросами, лимиты бесплатного тарифа), без координат или при осечке
   геокодера → `normalizeAddress`. Идемпотентен (повторный запуск не меняет
   уже чистые строки). Скрипт делает `prisma.listing.update`, что **бампает
   `updated_at`** у всех задетых объявлений — принято как приемлемая
   побочность одноразовой ops-операции, не влияет на бизнес-логику (нет мест,
   где `updated_at` объявления используется как источник истины для
   сортировки/уведомлений).
7. **Сиды** (`seed-all.cjs`) генерируют адрес сразу в целевом формате: `address`
   из `region.nameRu` (без префикса «город »/«г. ») + `district.nameRu` +
   улица + дом; `address_en` — из `region.nameEn` (без суффикса « shahri») +
   `district.nameEn` + та же улица/дом. Важная деталь: `name_en` регионов/районов
   в БД — фактически узбекская латиница («Toshkent shahri», «Mirzo-Ulugbek»),
   не литературный английский перевод (апостроф/спецсимвол в этой латинице не
   гарантирован — конкретно у района дефис, без апострофа); en-адрес намеренно
   использует те же значения, что и `district_name` в остальной выдаче
   (фильтры, детали) — расхождения между «районом на карточке» и «районом в
   адресе» не создаём.

## Consequences

Positive:

- Адрес на карточках/детали больше не содержит дублей района/города и «город
  »-мусора независимо от источника (Suggest, drag-геокод, сиды).
- Появилась en-версия адреса (`address_en`) для будущей выдачи по локали
  (PR-2), без миграции `listing_translations` и без нарушения инварианта
  «переводы полны только после модерации» (ADR-0091).
- Best-effort геокодер не создаёт новую точку отказа: пустой/просроченный
  ключ, сетевой сбой или лимит тарифа деградируют до строковой нормализации,
  а не до 500.

Negative / trade-offs:

- Качество en-адреса — транслит структурных компонентов Yandex («Seul
  koʻchasi»), не литературный перевод; для города/района это те же значения,
  что уже используются сайтом (`districts.name_en`), поэтому воспринимается
  консистентно, а не как отдельный баг.
- `q` ILIKE-поиск по адресу не меняется и продолжает работать по каноническому
  `listings.address` (русский); en-адрес не индексируется отдельно — поиск на
  en-локали ищет по тем же ru-строкам.
- `update` без `address` в dto при недоступном геокодере оставляет адрес
  устаревшим относительно новых координат (см. п.5) — принят как риск,
  закрытый текущим UI визарда.
- Backfill бампает `updated_at` у всех обработанных объявлений — приемлемо для
  one-off операции, но делает поле непригодным для отличения «правда
  отредактировано пользователем» от «прогнан backfill», если такой сценарий
  понадобится в будущем.
- Бесплатный тариф HTTP Геокодера ограничен по RPS/квоте в сутки — backfill
  работает с паузой 300ms между запросами; при большом объёме объявлений в
  проде потребуется либо платный тариф, либо более длинная пауза/батчинг.
