# ADR-0148 — Редизайн публичного каталога агентов /agents

## Status

Accepted

## Date

2026-07-20

## Context

Страница `/agents` появилась в PR #415 как минимальный каталог: сетка 1/2/3/4
компактных карточек `AgentCard` (те же, что на главной) + кнопка «Показать
ещё» по 24 агента. Найти конкретного агента на ней невозможно — только
глазами по сетке, а `about` в карточку не помещался вовсе.

Ориентир редизайна — каталог профессионалов Zillow
(`professionals/real-estate-agent-reviews`): широкие строки, поиск по имени,
сортировка, счётчик результатов.

Ограничение, определившее половину решений: **API отдаёт только**
`{ id, name, avatar_url, agency_name, about, active_listings_count }`
(API.md §21). Ни рейтингов, ни отзывов, ни телефонов, ни статистики сделок,
ни региона агента в модели данных нет.

## Decision

1. **Список широких строк вместо сетки карточек.** Новый
   `features/agents/AgentRow.tsx`: аватар 72px (96px на десктопе), имя, под
   ним агентство или «Частный маклер», `about` в две строки (`line-clamp-2`),
   мятная пилюля «N активных объявлений» и две кнопки — «Профиль»
   (`/agents/:id`) и «Объявления» (`/search?agent_id=:id`). Полезного текста
   у агента больше, чем влезает в плитку; плитки при этом были почти пустые.
   Сетка компактных карточек остаётся на главной — `AgentCard` не тронут по
   виду, из него лишь вынут общий `AgentAvatar` (фото → инициал → иконка),
   чтобы логика fallback'ов не разъезжалась между двумя компонентами.
2. **Строка не является ссылкой целиком.** Внутри строки две кнопки-ссылки;
   интерактив внутри `<a>` — невалидный HTML и ломает клавиатурную
   навигацию. Ссылкой сделано имя агента, вся строка подсвечивается тенью
   через `group-hover`.
3. **Весь каталог одним SSR-запросом:** `AGENTS_CATALOG_LIMIT = 100` (максимум,
   который допускает API) вместо `AGENTS_PAGE_SIZE = 24`. Роль агента
   выдаётся модерацией, каталог небольшой и целиком помещается в одну
   страницу.
4. **Поиск и сортировка — на клиенте, по массиву в памяти.** Поиск —
   подстрока в `name`/`agency_name`, регистронезависимо, в `useMemo`; debounce
   не нужен (фильтрация синхронная, сети нет). Сортировка — существующий
   `ui/dropdown` (single-select обязан использовать `DropdownItem`, иначе меню
   не закрывается): «Сначала активные» (порядок API) и «По имени (А–Я)»
   (`localeCompare`, агенты без имени — в конец). Это прямое следствие п.3:
   раз SSR отдал весь каталог, поиск честно ищет по всему каталогу, а не по
   подгруженному куску.
5. **«Показать ещё» осталась, но условно:** видна, только если
   `agents.length < total` **и** поиск пуст. При активном поиске дотянутая
   страница всё равно не попала бы в фильтр, а счётчик «Найдено N» дёргался
   бы без видимой причины.
6. **Пустой результат поиска ≠ пустой каталог:** отдельный ключ `noResults` со
   ссылкой «Сбросить поиск»; `empty` остаётся сообщением «Агентов пока нет».
7. **Рейтинги, отзывы, телефоны, статистику сделок и регион не показываем** —
   этих полей нет ни в модели агента, ни в БД. Показать их можно было бы
   только выдумав, а Zillow-подобная строка с фейковыми пятью звёздами —
   прямой обман пользователя.

## Consequences

Positive:

- Агента можно найти по имени или агентству за одно нажатие, без прокрутки.
- `about` наконец виден в каталоге — строка несёт больше сигнала, чем плитка.
- Ни одной новой зависимости; ни одного нового эндпоинта и параметра API.
- Поиск и сортировка мгновенные — сети на каждое нажатие нет.
- Главная не затронута: `AgentCard` и её сетка выглядят как раньше.

Negative / trade-offs:

- **Решение живёт, пока агентов ≤ 100.** Когда каталог перерастёт лимит,
  клиентские поиск и сортировка начнут врать (будут работать только по
  загруженной части). Тогда их надо переносить на сервер — в параметры
  `GET /agents` (`q`, `sort`), а страницу возвращать к постраничной загрузке.
  Порог зафиксирован в комментарии у `AGENTS_CATALOG_LIMIT`.
- Один SSR-запрос на 100 агентов тяжелее, чем на 24 — приемлемо: строка
  агента маленькая, ответ кэшируется на час (`revalidate: 3600`).
- Поиск не учитывает опечатки и не ищет по `about` — намеренно: подстрочный
  матч предсказуем, а fuzzy-поиск потребовал бы зависимости.
- Состояние поиска/сортировки не попадает в URL (в отличие от `/search`) —
  ссылкой на отфильтрованный каталог поделиться нельзя. Для каталога из
  десятков строк это не выглядит нужным.
