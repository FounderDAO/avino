# ADR-0150: OTP-история в админке и прогрессивные лимиты resend

Дата: 2026-07-21. Статус: принят.

## Контекст

Поддержке нужен разбор жалоб «код не пришёл», а бюджет SMS не защищён от
злоупотребления: cooldown между запросами кода был фиксированным (60с,
`OTP_RESEND_COOLDOWN`) без суточного потолка — контакт мог получать SMS каждую
минуту неограниченно (SMS-bombing, расход бюджета). Отложенный hardening из
ADR-0012. Также временно скрыт пункт «Жалобы» из админ-навигации (страница и
API сохранены).

## Решение

1. **Прогрессивный cooldown** (`OtpRateLimitService.startCooldown`): номер
   запроса в rolling-окне 24ч (Redis `otp:req:{channel}:{dest}`, INCR + TTL)
   выбирает ступень 60с → 120с → 300с → 600с (множители ×1/×2/×5/×10 от
   `OTP_RESEND_COOLDOWN`). `resend_after` в ответе — фактическая ступень,
   клиентский таймер подстраивается без правок.
2. **Суточный кап**: ≥5 кодов на контакт за окно → 429 RATE_LIMITED
   (`assertCanRequest`). Константы в коде — без новых env-кнобок.
3. **Журнал OTP**: `GET /api/v1/admin/otp-logs` (ADMIN-only, паттерн
   admin-журналов) поверх `otp_codes` (записи не удаляются): контакт, канал,
   назначение, попытки, вычисляемый статус (ACTIVE / CONSUMED «Погашен» —
   использован или заменён новым / EXPIRED), пользователь. `code_hash` наружу
   не отдаётся. Страница `/admin/otp-history` (группа «Система») с поиском по
   контакту.

## Последствия

- Легитимный пользователь при недоставке: 2-й код через минуту, далее ожидание
  растёт; максимум 5 SMS/сутки на номер — потолок расходов.
- IP-лимиты, verify-лимиты и брутфорс-лок не изменены.
- Лимиты общие для LOGIN и CONTACT_CHANGE (ключи per channel+destination).
