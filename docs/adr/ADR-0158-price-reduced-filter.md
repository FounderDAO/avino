# ADR-0158 — Фильтр «Цена снижена» (price_reduced)

## Status

Accepted

## Date

2026-07-29

## Context

Нужен фильтр «только со снижением цены» в публичном поиске. История цен уже
пишется (ADR-0121, `listing_price_history`), но вычислять направление
последнего изменения на каждый поиск (LATERAL по двум последним записям
истории) дорого и неиндексируемо.

## Decision

Денормализованная колонка `listings.price_reduced boolean NOT NULL DEFAULT false`:

- пишется ТОЛЬКО рядом с записью `listing_price_history` в
  `ListingsService.update()` (одна транзакция — рассинхрон исключён);
- снижение цены в той же валюте → `true`; повышение → `false`; смена валюты →
  `false` (цены в разных валютах несравнимы); no-op флаг не трогает;
- флаг вечный — живёт до следующего повышения (затухания по времени нет);
- backfill существующих объявлений в миграции (две последние записи истории);
- поиск: `?price_reduced=true` → `WHERE price_reduced = true` + частичный
  индекс `WHERE price_reduced = true`; `false`/отсутствие — без фильтра
  (паттерн фильтров-флажков);
- фильтр работает во всех поисковых эндпоинтах (`/search`, `/search/bounds`,
  `/search/radius`, `/search/polygon`, `/search/clusters`).

## Consequences

- Бейдж «Цена снижена» на карточках — отдельная задача (поле в card-shape не
  добавлялось).
- Админ-путей записи цены нет; если появятся — обязаны проходить через ту же
  точку записи истории и флага.
- **Сохранённые поиски с фильтром `price_reduced`**: saved-search-алерты
  (email-уведомления о новых совпадениях) **не срабатывают на снижение цены
  уже опубликованного объявления**. Это закономерно: матчер алертов ходит
  окном по `published_at`, который проставляется при первой публикации
  объявления и не перезаписывается при ремодерации; поэтому снижение цены —
  обновление без смены `published_at` — алертом не ловится. Фильтр влияет
  только на браузинг-выдачу и восстановление сохранённого поиска по ссылке.
