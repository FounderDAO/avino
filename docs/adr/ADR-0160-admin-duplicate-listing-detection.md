# ADR-0160 — Детекция дубликатов объявлений в модерации

## Status

Accepted

## Date

2026-10-01

## Context

Пользователи (в т.ч. разные аккаунты) публикуют одно и то же объявление
повторно. Модератор в очереди не видит, что такой объект уже есть в базе, и
одобряет дубль. Нужен сигнал «такое объявление уже существует» прямо в карточке
модерации со ссылкой на существующее объявление.

Варианты критерия совпадения: точный заголовок (бесполезен — заголовки
свободные), fuzzy-похожесть текста (pg_trgm `similarity()` — ложные
срабатывания, нужен подбор порога), совпадение ключевых полей объекта.

Варианты момента проверки: писать флаг в БД при создании объявления
(протухает при правках цены/адреса любого из пары, нужна миграция и
инвалидация) или считать «на лету» при открытии карточки модерации.

## Decision

1. **Критерий**: дубликат = совпадение `price` + `area` + `total_floors` +
   `address` (адрес нормализуется в SQL: `lower(regexp_replace(btrim(...),
   '[[:space:]]+', ' ', 'g'))` — без учёта регистра и лишних пробелов).
   Кандидаты — только статусы `NEW`/`ACTIVE`; REJECTED/DRAFT/терминальные не
   считаются (их повторная публикация легитимна). Без `address` у источника —
   пустой ответ (надёжная детекция невозможна).
2. **Момент**: проверка на лету — новый endpoint
   `GET /api/v1/admin/listings/:id/duplicates` (MODERATOR/ADMIN), который
   админка зовёт при открытии карточки модерации и админ-детали. В БД ничего
   не хранится, флаг не протухает, миграция не нужна.
3. **Реализация**: `ModerationService.findDuplicates` — raw-SQL поиск id
   кандидатов (null-безопасные равенства `IS NOT DISTINCT FROM`, LIMIT 10,
   свежие первыми) + Prisma-выборка карточек (reference, статус, цена,
   площадь, этажность, адрес, title на языке оригинала, обложка
   sign-on-read по ADR-0086).
4. **UI (apps/web)**: блок-предупреждение «Возможный дубликат — найдено N
   совпадений» в карточке модерации (`/admin/moderation`) и на админ-детали
   (`/admin/listings/[id]`); рендерится только при непустом ответе. Клик по
   строке → модалка предпросмотра существующего объявления (стиль
   PromoteListingModal). Данные — RTK Query `getListingDuplicates`
   (тег `Admin`).

## Consequences

Positive:

- Модератор видит дубль до одобрения; причина отклонения «Подозрение на
  дубликат» уже есть в наборе.
- Нет новых таблиц/колонок/миграций; сигнал всегда свежий.
- Точный критерий по полям объекта — предсказуемый, без ложных срабатываний
  fuzzy-похожести.

Negative / trade-offs:

- Запрос с `regexp_replace` по `listings` не использует индекс (посчитан
  приемлемым: вызывается точечно модератором, выборка уже сужена равенством
  по `price`, у которого индекс есть).
- Перефразированный адрес или изменённая на 1 у.е. цена обходят детекцию —
  осознанный компромисс против ложных срабатываний.
