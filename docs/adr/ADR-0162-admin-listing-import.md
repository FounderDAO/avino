# ADR-0162 — Массовый импорт объявлений админом

## Status

Accepted

## Date

2026-10-02

## Context

Админу нужно заводить объявления пачками из таблицы (10–200 строк), где владелец
задан телефоном. До этого объявление создавал только сам владелец через
`POST /listings`; админского создания объявления и пользователя не было.

## Decision

- Импорт — отдельный модуль `listing-imports`, роуты `/admin/listing-imports`,
  только `ADMIN`.
- Один эндпоинт с флагом `dry_run`: предпросмотр и запуск классифицируют строки
  одним кодом. Файл не хранится и передаётся дважды.
- Обработка синхронная, лимит 500 строк и 2 МБ; транзакция на строку; один
  импорт одновременно (блокировка в Redis).
- Владелец ищется по телефону; если его нет — создаётся пользователь с
  неподтверждённым телефоном, ролью USER и профилем из файла. Телефон
  подтверждается при первом OTP-входе.
- Импорт не вызывает `ensureProfileComplete` и `ensureActiveListingQuota`.
  Инвариант ADR-0125 (у автора есть имя и фамилия) импорт обеспечивает сам;
  лимит активных объявлений на админский импорт не распространяется.
- «Уже существует» — в рамках владельца: тип сделки, тип недвижимости,
  нормализованный адрес, площадь, площадь участка, этаж; статус не `DELETED`.
  Цена в ключ не входит. Это отдельный от ADR-0160 критерий: там ищутся похожие
  объявления у любых владельцев для модератора.
- Объявления создаются в `NEW` без геокодинга и без фото; переводы генерирует
  модератор (ADR-0091).
- `ListingsService.create` разделён на `buildCreateData` и
  `createInTransaction`; обычное создание и импорт пишут объявление одним кодом.

## Consequences

Positive:
- Повторная загрузка файла безопасна: созданные строки пропускаются.
- Каждый запуск сохранён (`listing_imports`, `listing_import_rows`, `audit_logs`).
- Правила полей объявления не дублируются — используется `CreateListingDto`.

Negative / trade-offs:
- Опечатка в телефоне создаёт аккаунт на чужой номер.
- Ключ чувствителен к написанию адреса: нормализуются регистр, пробелы и то, что
  умеет `normalizeAddress`.
- Объявления без координат не попадают на карту и в геопоиск.
- Владелец может оказаться выше лимита активных объявлений.
- Рост объёма или импорт фото потребуют фоновой очереди.
