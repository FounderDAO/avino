# ADR-0163 — Модераторское действие ARCHIVE и массовая архивация

## Status

Accepted

## Date

2026-10-02

## Context

Заказчик пожаловался: массовый перенос объявлений в архив в админке не
работает. Причин две. (1) Кнопки панели «Выбрано: N» в `/admin/listings`
(«Одобрить», «В архив») пришли из прототипа `apps/claudeDesign` как заглушки —
показывали тост об успехе и не слали запросов. (2) У модератора вообще не было
пути в `ARCHIVED`: `PATCH /admin/listings/:id/status` принимал только
`APPROVE | SEND_TO_DRAFT | REJECT | DELETE`, статус `ARCHIVED` был
зарезервирован за владельцем (`HIDE`).

Варианты транспорта массового действия: отдельный bulk-эндпоинт или цикл по
существующему `PATCH` на клиенте.

## Decision

1. **Новое действие** `ModerationAction.ARCHIVE` → `ListingStatus.ARCHIVED`
   (миграция `ALTER TYPE ... ADD VALUE`). Исходные статусы — те же
   `MODERATABLE_STATUSES` (`NEW | ACTIVE | DRAFT | REJECTED`), что и у
   владельческого `HIDE`; из `ARCHIVED | SOLD | RENTED` →
   `422 INVALID_STATUS_TRANSITION`. Как и прочие решения модератора, пишет
   `moderation_logs` + `audit_logs` и ставит уведомление владельцу.
2. **Возврат владельцем.** Архив обратим: владелец может сделать `REACTIVATE`.
   Чтобы smart-return не обходил модерацию, `edited_since_hidden` при ARCHIVE
   ставится в `false` только для листинга, архивированного из `ACTIVE`; из
   `NEW | DRAFT | REJECTED` — `true`, и возврат идёт в `NEW`.
3. **Транспорт.** Bulk-эндпоинт не вводим: админка шлёт существующий `PATCH`
   по каждой выбранной строке (не более 5 одновременно). Отказ одной строки не
   прерывает остальные; тост показывает счётчики «применено / пропущено» с
   причинами (статус не позволяет, нет переводов и т.д.).
4. «Одобрить» в той же панели было такой же заглушкой — подключено тем же
   механизмом (гейт переводов ADR-0091 действует на каждую строку).

## Consequences

- Контракт `PATCH /admin/listings/:id/status` расширен non-breaking
  (новое значение `action`); `moderation_logs.action` может быть `ARCHIVE`.
- Деплой требует применения миграции enum, иначе запись лога падает.
- Массовое действие не атомарно и даёт N запросов (и N рефетчей списка); при
  росте выборок — кандидат на серверный bulk-эндпоинт.
- Чтобы объявление нельзя было вернуть, модератору по-прежнему нужны
  `REJECT`/`DELETE`: архив владелец может отменить сам.
