# ADR-0165 — Импорт фото при массовом импорте объявлений

## Status

Accepted

## Date

2026-10-03

## Context

Массовый импорт (ADR-0162) создавал объявления без фото. Фото импортируемых
объектов лежат и по прямым ссылкам, и в папках на компьютере админа. ZIP-архивы
потребовали бы загрузки по частям и распаковки на сервере.

## Decision

- Колонка «Фото»: ссылки и имена файлов в одной ячейке, порядок = порядок галереи.
- Ссылки скачивает сервер: BullMQ `listing_import_photo_queue`, одна задача на
  фото, SSRF-защита (`net.BlockList`, проверка адреса в `lookup` при соединении,
  ручные редиректы ≤ 3, сниффинг байтов, 10 МиБ, 15 с).
- Файлы из папки загружает браузер по одному на
  `PUT /admin/listing-imports/:id/photos/:photoId`; совпадение по имени файла.
- Статусы — таблица `listing_import_photos`; записи создаются в транзакции строки.
- Ошибки синтаксиса ячейки — ошибка строки; ошибки загрузки — ошибка фото,
  объявление создаётся.
- Строка «уже существует» получает фото, если у объявления 0 фото и нет
  незавершённых фото другого импорта.
- Обработка изображений (EXIF/GPS, миниатюры) не добавляется — паритет с
  обычной загрузкой.

## Consequences

Positive:
- Нет гигабайтных загрузок; повтор и дозагрузка поштучно; история импортов.
- Общий путь записи в галерею (`uploadToStorage` + `createMediaRecord`), чистка
  «сирот» продолжает работать.

Negative / trade-offs:
- Файлы из папки грузятся, пока открыта вкладка; недогруженное дозагружается из истории.
- EXIF/GPS в фото сохраняется (отдельная задача с `sharp`).
- Сайты, блокирующие ботов, дают `HTTP_ERROR`; запасной путь — галерея в карточке.
