# ADR-0166 — Надёжность автоперевода: причина сбоя, длинный текст, проверка языка оригинала

## Status

Accepted (дополняет ADR-0091, ADR-0156)

## Date

2026-10-03

## Context

Клиент пожаловался, что автоперевод «не работает как надо». Проверка показала:

- API-ключ Yandex Translate истёк (2026-07-31) → Yandex `401` → `502` у
  `POST /admin/listings/:id/translations/generate`. Контроллер глотал ошибку без
  лога, провайдеры отбрасывали тело ответа, UI показывал «Не удалось
  сгенерировать переводы» — причину нельзя было узнать ниоткуда.
- Форма подачи (`apps/client`) всегда ставила язык оригинала `RU`. Узбекский
  текст с `original_language=RU` Yandex возвращает непереведённым; русский с
  `UZ` — транслитом.
- Yandex принимает не более 10 000 символов на запрос; у `description` лимита
  длины нет → длинное описание срывало всю генерацию (`400`).
- Редакторы панели «Переводы» (`apps/web`) держали текст в локальном стейте с
  `key=language`: после генерации и при смене объявления в очереди поле
  показывало старый/чужой текст.

## Decision

1. **Причина сбоя провайдера не теряется.** Провайдеры включают в ошибку статус и
   сообщение из тела ответа (обрезка 300 символов); контроллер логирует её и
   отдаёт в `message` ответа `502`: `Translation provider failed: <причина>`.
   Web показывает её в тосте.
2. **Длинный текст переводится частями.** Yandex-провайдер режет текст на части
   ≤ 10 000 символов по мягким границам (перевод строки → конец предложения →
   пробел), пробельные края частей не отправляет и возвращает как были.
   Ограничение длины `description` в DTO не вводим — это сломало бы контракт для
   мобильных клиентов и существующих данных.
3. **Проверка языка оригинала — подсказка, не блокировка.** `generate` определяет
   язык авторского текста (Yandex `detect`, подсказки `uz/ru/en`, `uzbcyr` → UZ;
   текст короче 20 символов не проверяется) и возвращает `detected_language`.
   При несовпадении с `original_language` админка показывает предупреждение;
   перевод всё равно выполняется, язык оригинала исправляет модератор
   (ADR-0156). Метод `detectLanguage` в интерфейсе провайдера необязателен; сбой
   определения генерацию не срывает.
4. **Язык оригинала по умолчанию = язык интерфейса** в форме подачи (`/uz` → UZ,
   `/en` → EN, иначе RU).
5. **`key` строки перевода** в админке включает id объявления и серверный текст.

## Consequences

Positive:

- Истёкший/неверный ключ диагностируется за секунды (лог + тост).
- Меньше объявлений с неверным `original_language`; оставшиеся модератор видит.
- Длинные описания больше не срывают генерацию.

Negative / trade-offs:

- Один дополнительный запрос к Yandex (`detect`) на каждую генерацию.
- Смешанный русско-узбекский текст определяется как один язык — предупреждения
  может не быть.
- Для `TRANSLATE_PROVIDER=google` определение языка не реализовано
  (`detected_language` всегда `null`).
- Вне scope (как и в ADR-0091): мягкая деградация без ключа (копия оригинала) и
  устаревание переводов после правки объявления владельцем.
