# Ипотечный калькулятор Avino — спецификация для веб-версии

> Промпт/ТЗ для веб-разработчика. Описывает **полную** логику ипотечного
> калькулятора мобильного приложения (Flutter), которую нужно 1:1 повторить
> на вебе. Источник истины — код приложения:
> `lib/core/formatting/mortgage_estimate.dart` (вся математика),
> `lib/features/listings/presentation/mortgage/*` (экраны и state),
> `lib/features/listings/data/mortgage_prefs_store.dart` (персистентность).

---

## 1. Общая идея

Калькулятор отвечает на вопрос: **«потяну ли я ипотеку на эту квартиру?»**

- Всегда открывается **от конкретного объявления** — цена берётся из него и
  не редактируется пользователем.
- Всё считается **на клиенте**. Никаких запросов на бэкенд: зарплата
  пользователя приватна и **никогда не покидает устройство** (хранится только
  в localStorage / SharedPreferences).
- Валюта расчёта = валюта показа цен, выбранная пользователем в приложении
  (UZS или USD). Цена объявления при необходимости конвертируется по курсу
  `/exchange-rate` на клиенте.
- Решение «одобрят/не одобрят» — по правилу **DTI: ежемесячный платёж не
  должен превышать 40% месячной зарплаты**.

Функционально это 4 части:

1. **Est-полоска** на детали объявления — «Oyiga ~$460/oy» + ссылка «Рассчитать ипотеку».
2. **Карточка «Ежемесячный платёж»** на детали — оценка платежа + разбивка первый платёж: тело/проценты.
3. **Экран ввода** (форма калькулятора).
4. **Экран результата** — вердикт OK/NO, DTI-шкала, рекомендация, разбивка сумм.

## 2. Константы (единый источник истины)

| Константа | Значение | Смысл |
|---|---|---|
| `downPaymentRatio` | 20% | Дефолтный первоначальный взнос |
| `loanTermYears` | 20 лет | Дефолтный срок |
| `uzsAnnualRate` | 22% | Дефолтная годовая ставка для расчёта в UZS |
| `usdAnnualRate` | 8% | Дефолтная годовая ставка для расчёта в USD |
| `dtiLimitPct` | 40% | Лимит банка: платёж ≤ 40% зарплаты |

Дефолтная ставка выбирается по валюте показа: USD → 8%, UZS → 22%.

## 3. Математика

### 3.1 Аннуитетный платёж

Вход (`MortgageInput`): `price` (цена, в валюте показа), `salary`
(зарплата/мес, та же валюта), `downPct` (взнос, %), `annualRatePct`
(годовая ставка, %, например `8.0` = 8%), `years` (срок, лет).

```
downPayment = price * downPct / 100
principal   = price - downPayment          // тело кредита
n           = years * 12                   // число платежей
r           = annualRatePct / 100 / 12     // месячная ставка

если r == 0:  monthlyRaw = principal / n
иначе:        monthlyRaw = principal * (r * (1+r)^n) / ((1+r)^n - 1)

monthly       = round(monthlyRaw)          // округление до целой единицы валюты
totalPaid     = monthly * n                // именно от округлённого платежа!
totalInterest = totalPaid - principal
dtiPct        = salary <= 0 ? 100 : round(monthly / salary * 100)  // целый %
affordable    = dtiPct <= 40
```

Правила округления (важно для сходимости с мобильным приложением):
- `monthly` — до целой единицы валюты (обычное математическое round);
- `dtiPct` — до целого процента;
- `totalPaid` считается от **уже округлённого** `monthly`.

### 3.2 Рекомендация «как сделать доступным» (`suggestFix`)

Вызывается **только когда** `affordable == false`. Приоритет строго такой:

1. **Продлить срок.** Перебираем `y = years+1 … 30` (шаг 1 год). Первый `y`,
   при котором DTI ≤ 40% → рекомендация «Рассчитать с {y} годами»
   (показываем новый платёж и новый DTI). Кнопка применяет `years = y`.
2. **Увеличить взнос.** Если и 30 лет не спасают: перебираем
   `d = downPct+5, +10, … 60` (шаг 5 п.п., максимум 60%), каждый вариант
   проверяем **на сроке 30 лет**. Первый подходящий `d` → рекомендация
   «Рассчитать со взносом {d}%». Кнопка применяет **сразу оба** параметра:
   `downPct = d` **и** `years = 30`.
3. **Снизить бюджет.** Если ничего не помогло — считаем максимально доступную
   цену и предлагаем «Смотреть дома до {maxPrice}». Кнопка ставит фильтр
   поиска `priceTo = maxPrice` (+ текущая валюта) и уводит на карту/каталог.

### 3.3 Максимально доступная цена (`maxAffordablePrice`)

Обратный аннуитет: цена, при которой платёж на **30-летнем** сроке ровно
40% зарплаты, с учётом доли кредита:

```
clampedDownPct = clamp(downPct, 0, 99)     // защита от деления на 0 при 100%
budget = salary * 40 / 100                 // допустимый платёж
n = 30 * 12
r = annualRatePct / 100 / 12

если r == 0: principal = budget * n
иначе:       principal = budget * ((1+r)^n - 1) / (r * (1+r)^n)

maxPrice = principal / (1 - clampedDownPct / 100)
```

Перед подстановкой в фильтр поиска цена «красиво» округляется **вниз**:
USD — до тысяч, UZS — до миллионов.

## 4. Экран ввода (форма)

### 4.1 Шапка — мини-карточка объекта

Фото 48×48 (заглушка-плейсхолдер, если фото нет), заголовок
«{цена} · {N комнат}» (комнаты опускаются, если их нет), адрес. Всё в одну
строку с ellipsis.

### 4.2 Поля

| Поле | Тип | Диапазон/шаг | Дефолт | Примечание |
|---|---|---|---|---|
| Зарплата в месяц | текстовое, только цифры | до 13 цифр | пусто | Живая группировка тысяч запятыми при вводе («1,400»). Суффикс в поле: `$ /мес` или `сум /мес` по валюте. |
| Первоначальный взнос | чипы | 15 / 20 / 30 / 40 % | 20% | Один выбранный чип. Чип подсвечивается **только при точном совпадении** — рекомендация может выставить, например, 45%, тогда не подсвечен ни один. |
| Годовая ставка | слайдер | 1–24%, шаг 0.5 | 22% (UZS) / 8% (USD) | Текущее значение крупно справа от лейбла. |
| Срок | слайдер | 5–30 лет, шаг 1 год | 20 лет | — |

Под чипами взноса — живая строка-разбивка: «{взнос} взнос · {кредит} кредит»
(пересчитывается от цены при каждом изменении `downPct`).

### 4.3 CTA «Рассчитать»

Активна только когда `salary > 0`. Ведёт на экран результата. Никакой
валидации остальных полей не нужно — слайдеры/чипы не дают невалидных значений.

### 4.4 Персистентность (автосохранение)

**Каждое** изменение любого поля немедленно сохраняется локально
(fire-and-forget, UI не блокируется). Ключи:

- `mortgage_salary` (число) + `mortgage_salary_currency` (`USD`/`UZS`) — в
  какой валюте была введена зарплата. Очистка поля → удалить оба ключа.
- `mortgage_down_pct` (int)
- `mortgage_rate_pct_usd` и `mortgage_rate_pct_uzs` — **ставка хранится
  отдельно для каждой валюты** (у UZS и USD разные рыночные ставки). Меняя
  ставку в режиме USD, пользователь не трогает сохранённую UZS-ставку.
- `mortgage_years` (int)

При открытии формы сохранённые значения подгружаются и подставляются:

- Зарплата, сохранённая **в другой валюте**, конвертируется по текущему курсу
  и округляется до целого. Если курс недоступен — поле оставить пустым (не
  показывать число в чужой валюте).
- Отсутствующие значения → дефолты (20%, 20 лет, ставка по валюте).
- **Гонка «загрузка vs пользователь»:** если пользователь успел изменить поле,
  пока асинхронно грузились сохранённые значения, — его ввод побеждает,
  загруженные значения не применяются.
- Поле зарплаты префиллится сохранённым значением ровно один раз и только
  если пользователь ещё ничего не ввёл.

### 4.5 Смена валюты показа

Если пользователь переключил UZS↔USD, пока калькулятор открыт, — состояние
пересоздаётся: зарплата переконвертируется, ставка берётся сохранённая для
новой валюты (или дефолтная), цена объявления пересчитывается.

## 5. Экран результата

Состояние формы и результата — **общее** (один store): кнопки рекомендаций
мутируют его, и результат пересчитывается на месте, без возврата к форме.

Сверху вниз:

1. **Бейдж-вердикт** (пилюля с иконкой в круге):
   - OK «Вписывается в бюджет» — фон `#E7F3EA`, текст `#166534`, зелёный круг с галочкой;
   - NO «Пока не вписывается» — фон `#FBEEEE`, текст `#8C2F33`, красный круг с крестом.
2. **Платёж крупно**: `{monthly} /мес` (40px), под ним строка
   «{N лет} · {ставка}% годовых · {кредит} кредит».
3. **DTI-шкала**: горизонтальный бар 0–100%, заливка = `min(dtiPct, 100)`,
   цвет зелёный (OK) / красный (NO). На отметке 40% — вертикальная чёрная
   черта с подписью «40%» **под** баром. Справа над баром — само значение
   `{dtiPct}%` цветом вердикта. Под шкалой пояснение:
   - OK: «Ежемесячный платёж — {pct}% вашей зарплаты, ниже требуемых банком {40}%.»
   - NO: «…выше допустимых банком {40}%.»
4. **Карточка-рекомендация** (только при NO) — см. §3.2. Заголовок
   «Чтобы получилось», текст и одна кнопка-действие. После нажатия кнопки
   параметры меняются, экран пересчитывается — вердикт становится OK и
   карточка исчезает.
5. **Таблица-разбивка** (6 строк, лейбл слева, значение справа):
   - Цена дома — `price`
   - Первоначальный взнос ({downPct}%) — `downPayment`
   - Сумма кредита — `principal`
   - Платёж в месяц — `monthly`
   - Всего выплат (за {N лет}) — `totalPaid`
   - Переплата (проценты) — `totalInterest`
6. **«Пересчитать»** — ссылка назад к форме (обычный back; при прямом
   диплинке на результат, когда стека нет, — переход на форму).
7. **Дисклеймер**: расчёт предварительный, не является офертой банка.

Edge-cases результата:
- Прямой заход на URL результата, пока сохранённые данные ещё грузятся —
  спиннер (не мигать фолбэком).
- Прямой заход без сохранённой зарплаты (`salary <= 0`) — не считать,
  показать только кнопку «Пересчитать», ведущую к форме.

## 6. Виджеты-оценки на странице объявления

Оба виджета используют **сохранённые параметры пользователя** (взнос, ставка
своей валюты, срок), а при их отсутствии — дефолты. Зарплата им не нужна
(DTI не считается). Реактивность: изменил параметры в калькуляторе → цифры
на детали объявления обновились сразу.

### 6.1 Est-полоска

Мятная полоска: «Oyiga ~{monthly}/oy» + ссылка «Рассчитать ипотеку» → экран
формы. `monthly` — тот же `calculateMortgage`, цена в валюте показа.

### 6.2 Карточка «Ежемесячный платёж»

- Лейбл «Оценка» с info-иконкой, платёж крупно `{monthly} /мес`;
- строка параметров: «{downPct}% взнос · {rate}% годовых · {N лет}»;
- **структура первого платежа аннуитета** (легенда с двумя цветами + stacked
  bar, доли пропорциональны суммам):
  ```
  interest      = round(principal * annualRatePct / 100 / 12)  // проценты на весь кредит
  principalPart = monthly - interest                           // остальное гасит тело
  ```
- ссылка «Настроить расчёт» → экран формы.

---

## 7. Форматирование

- Суммы — целые, с группировкой разрядов по локали (`1 250 000 сум`, `$1,400`).
- Ставка может быть дробной (шаг 0.5): показывать «8%» без дробной части,
  если целая, иначе «8.5%».
- Локализация: узбекский / русский / английский. Все строки — в ресурсах
  (ключи `mortgage*` в ARB-файлах приложения можно взять как референс
  полного списка текстов).

## 8. Чек-лист приёмки

- [ ] Формула аннуитета и все округления совпадают с §3.1 (тест: одинаковые
      входы дают тот же `monthly`, что и мобильное приложение).
- [ ] DTI = 40% ровно → вердикт OK (`<=`, не `<`).
- [ ] `salary <= 0` на результате → DTI 100%, но в норме туда не попасть (CTA задизейблена).
- [ ] Ставка 0% не роняет расчёт (линейное деление) — на слайдере недостижима (min 1%), но функция обязана выдерживать.
- [ ] Приоритет рекомендаций: срок → взнос (с years=30) → бюджет.
- [ ] Кнопка «взнос {d}%» ставит и взнос, и 30 лет одновременно.
- [ ] Ставки USD и UZS хранятся независимо.
- [ ] Зарплата конвертируется при смене валюты; без курса — поле пустое.
- [ ] Зарплата не отправляется ни в какие API.
- [ ] Изменения в калькуляторе мгновенно обновляют est-полоску и карточку платежа.
- [ ] Чип взноса подсвечен только при точном совпадении (15/20/30/40).
