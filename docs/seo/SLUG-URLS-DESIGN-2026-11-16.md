# Avino — человекочитаемые адреса лендингов (фаза 8, дизайн)

**Статус:** предложение. Код не написан — нужно решение владельца.
**Дата:** 2026-11-16

## Зачем

Сейчас лендинги поиска — query-адреса с UUID:
`/ru/search?tx=SALE&district_id=d0000000-0000-4000-8000-000000000012`.

Слова в адресе — слабый, но реальный сигнал релевантности. Ещё важнее, что такую ссылку охотнее
публикуют и на неё нажимают. Адрес вида `/ru/prodazha/kvartiry/toshkent-shahri/yunusobod` понятен
человеку, поисковику и AI-ассистенту без расшифровки.

## Схема

```
/{locale}/{сделка}/{тип?}/{регион}/{район?}
```

| Сегмент | ru | uz | en |
|---|---|---|---|
| Продажа | `prodazha` | `sotuv` | `sale` |
| Аренда | `arenda` | `ijara` | `rent` |
| Квартиры | `kvartiry` | `kvartiralar` | `apartments` |
| Дома | `doma` | `uylar` | `houses` |
| Участки | `uchastki` | `yer-uchastkalari` | `land` |
| Коммерческая | `kommercheskaya` | `tijorat` | `commercial` |
| Новостройки (вместо типа) | `novostrojki` | `yangi-qurilish` | `new-construction` |
| Регион | код из API: `toshkent-shahri`, `samarqand`, … — одинаковый во всех языках | | |
| Район | slug из API, уникальный внутри региона: `yunusobod`, `chilonzor`, … | | |

Тип необязателен: `/ru/prodazha/toshkent-shahri` — вся продажа в Ташкенте.

**Рекомендация по языку slug'ов.**
- Слова «сделка» и «тип» — латиницей, своё слово для каждого языка (таблица выше).
- География — один slug из справочника API для всех трёх языков.

Почему не кириллица для ru:
- в адресе она превращается в `%D0%BF…` при копировании, в логах и в мессенджерах;
- три набора гео-slug'ов пришлось бы поддерживать вручную.

Один гео-slug на место проще, а hreflang при этом связывается по id.

## Что нужно от бэкенда

1. Поле `slug` у района, уникальное внутри региона, без числового хвоста.
   - Сейчас у 197 из 209 районов `code` вида `oqoltin-tumani-125`.
   - У 12 районов Ташкента код уже чистый: `yunusobod`, `chilonzor`.
2. Неизменность slug'ов. Если slug меняется, нужна таблица старый → новый для 301.
3. **Данные объявлений (блокер для пользы лендингов).**
   - У большинства активных объявлений нет `region_id`: под фильтром «Ташкент» 28 продаж из 1 236.
   - Почти нет `district_id`: в топе районов около 45 объявлений из 1 785.

   Без этого гео-лендинги будут пустыми, и с красивыми адресами тоже.

## Реализация во frontend (после одобрения)

1. Маршрут `src/app/[locale]/[deal]/[[...slug]]/page.tsx`.
   - Статические разделы (`about`, `help`, …) имеют приоритет над динамическим сегментом.
   - Неизвестная «сделка» → `notFound()`, как сейчас делает `[...rest]`.
2. Страница:
   - резолвит slug'и в id по кэшированным `getRegions` / `getDistricts`;
   - рендерит тот же компонент выдачи, что `/search`;
   - фильтры длинного хвоста остаются query-параметрами: `/ru/prodazha/doma/toshkent-shahri?priceMin=…` → noindex, follow.
3. `buildSearchCanonical` начинает отдавать slug-адрес. hreflang — тот же набор id в slug'ах каждого языка.
4. Sitemap включает только комбинации с ≥ 3 активными объявлениями. Пустой лендинг — noindex, чтобы не было soft-404.

## Матрица редиректов (301/308, один шаг)

| Старый адрес | Новый |
|---|---|
| `/{l}/search` и `/{l}/search?tx=SALE` | `/{l}/{продажа}` |
| `?tx=RENT` | `/{l}/{аренда}` |
| `?tx=…&type=HOUSE` | `/{l}/{сделка}/{дома}` |
| `?tx=…&new_construction=true` (и legacy `type=NEW_BUILDING`) | `/{l}/{сделка}/{новостройки}` |
| `?tx=…&region_id=R` | `/{l}/{сделка}/{регион R}` |
| `?tx=…&district_id=D` | `/{l}/{сделка}/{регион района D}/{район D}` |
| `?tx=…&type=…&district_id=D` | `/{l}/{сделка}/{тип}/{регион}/{район}` |
| Остальное: несколько `type`, `query`, цена, комнаты, `region_id=all`, карта, `agent_id` | без редиректа — query-адрес, noindex, follow |
| Лишние параметры при каноническом наборе (`view=list`, `cursor`) | редирект на slug-адрес без них |
| `page=N` | сохраняется: `/{l}/{сделка}/…?page=N` |

## Риски

| Риск | Что делаем |
|---|---|
| Пустые и тонкие лендинги (данные без региона и района) | Сначала данные; noindex для 0 объявлений; sitemap — от 3 объявлений |
| Временная просадка при переезде адресов | Один шаг 301; canonical, sitemap и внутренние ссылки меняются в том же релизе |
| Смена slug'а в справочнике | Неизменяемые slug'и плюс таблица 301 |
| Конфликт с будущими разделами верхнего уровня | Белый список значений «сделки» в каждом языке |
| Ташкент-город и Ташкентская область (`toshkent-shahri` и `toshkent`) | Разные slug'и, в заголовке — полное название |

- Backend: поле `slug` у района.
- Данные: заполнение региона и района у объявлений — отдельная задача.
