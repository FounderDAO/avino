# Spec — Zillow-фильтр цены (гистограмма + слайдер + вкладки)

**Дата:** 2026-06-27
**Статус:** одобрен (брейншторм), готов к плану
**Апп-папки:** `apps/api` (PR A) + `apps/client` (PR B)

## Проблема

Текущий фильтр цены (`FilterBar.tsx:418-448`) — простой dropdown с двумя
полями `от $ / до $` и коммитом по `onBlur`. По плану (Phase 1) он должен был
получить Zillow-вид, но гистограмма была отложена («нужен endpoint
распределения»). Сейчас визуально он отстаёт от референса Zillow (вкладки,
гистограмма распределения, слайдер с двумя ручками, поля Мин/Макс, «Применить»).

Дополнительно вскрыт **латентный баг**: клиентский `buildSearchParams`
(`apps/client/src/lib/api/listings.ts`) **не отправляет** параметр `currency`,
хотя бэкенд фильтрует цену в пределах валюты. Из-за этого ценовой фильтр
смешивает UZS- и USD-объявления (UZS 50000 и USD 50000 оба попадают в выдачу).

## Цель

Переделать фильтр цены в стиле Zillow: вкладки «Цена / Ежемесячный платёж»,
гистограмма распределения цен за слайдером, слайдер с двумя ручками, поля
Мин/Макс, кнопка «Применить». Всё работает **в текущей выбранной валюте**
(`displayCurrency` из глобального тоггла сум/$) и фильтрует ровно то, что
показывает гистограмма.

## Решения (зафиксированы в брейншторме)

| Вопрос | Решение |
|---|---|
| Гистограмма | **Делаем** (нужен новый backend-эндпоинт распределения). |
| Контекст гистограммы (v1) | **Глобальная** по (валюта + тип сделки). НЕ учитывает район/комнаты/полигон. Контекстную — отдельной фазой. |
| Вкладки List/Monthly Payment | **Оставляем.** «Цена» — рабочая. «Ежемесячный платёж» — заглушка с плашкой «Скоро» (ипотеки/рассрочки нет). |
| «Calculate your BuyAbility» | **Не делаем** (нет калькулятора). |
| Валюта фильтра | Текущая `displayCurrency`. Слайдер/гистограмма/порог — в её нативных значениях. FX в фильтрации нет (как в MVP). |
| Слайдер/Popover | Radix `Slider` (range) + Radix `Popover` — оба уже в зависимости `radix-ui ^1.5.0`, новых пакетов не добавляем. |

## Объём — 2 PR

Правило проекта: одна app-папка = отдельная ветка/PR; субагенты не трогают git.

- **PR A — `apps/api`:** эндпоинт распределения цен + DTO + сервис + int-spec +
  openapi(public) allowlist + regen + drift-check + ADR.
- **PR B — `apps/client`:** компонент `PriceFilter` (Popover + вкладки +
  гистограмма + слайдер + поля + «Применить») + фикс отправки `currency` +
  i18n. Деградирует без данных гистограммы → не блокируется PR A.

## Часть A — Backend: `GET /api/v1/search/price-distribution`

**Контроллер:** `search.controller.ts` (`@Controller({ path: 'search', version: '1' })`).
Публичный (как остальные `/search/*`).

**Query-параметры:**
- `currency` — `UZS | USD`, обязателен (`@IsEnum(Currency)`).
- `transaction_type` — `SALE | RENT`, обязателен (`@IsEnum(TransactionType)`).

**Видимость:** та же база, что у публичного `/search` — только видимые
объявления (ACTIVE/одобренные, не скрытые). Переиспользовать существующий
базовый предикат видимости из `search.service.ts`, не дублировать правила.

**Ответ** (response-DTO **обязан** лежать в `*.dto.ts` — иначе swagger-плагин
не задокументирует, и drift-check/openapi.public сломается):
```jsonc
{
  "currency": "USD",
  "transactionType": "SALE",
  "min": 0,                 // нижняя граница домена слайдера (всегда 0)
  "max": 500000,            // верхняя граница домена (p99-потолок)
  "buckets": [              // ~30–40 столбиков равной ширины по [min, max]
    { "from": 0,      "to": 12500,  "count": 3 },
    { "from": 12500,  "to": 25000,  "count": 7 }
    // …
  ],
  "overflowCount": 5        // объявлений строго выше max (хвост «$500K+»)
}
```

**Алгоритм (одна SQL-агрегация):**
1. `ceiling = percentile_cont(0.99)` по `price` среди видимых объявлений с
   данными `(currency, transaction_type)`. Если выборка пустая или `ceiling = 0`
   → вернуть `max=0`, `buckets=[]`, `overflowCount=0` (фронт деградирует).
2. `width_bucket(price, 0, ceiling, N)` (N ≈ 30–40) → `count(*)` по бакету.
   Бакеты с нулём — присутствуют (для ровной гистограммы), `count=0`.
3. `overflowCount = count(price > ceiling)`.
4. Округлить `ceiling` до «красивого» шага для домена (опц., для аккуратных
   подписей), но это не критично для v1.

**Кэширование (опц.):** распределение меняется медленно; короткий TTL-кэш по
ключу `(currency, transaction_type)` (in-memory/Redis). Можно отложить.

**OpenAPI:** новый публичный роут → добавить в public-allowlist
(`swagger.documents.ts`), прогнать `pnpm openapi:export` (+ dummy env),
зафиксировать `openapi.public.json`, зелёный drift-check.

**Тесты (int-spec):** пустая выборка → `max=0`/пустые бакеты; нормальная
выборка → сумма `count` бакетов + overflow = числу видимых объявлений
`(currency, transaction_type)`; невалидные/отсутствующие параметры → 400;
скрытые/не-ACTIVE объявления не учитываются.

**ADR:** зафиксировать решение (эндпоинт распределения, глобальный по
валюте+сделке, p99 + overflow, без FX).

## Часть B — Frontend: компонент `PriceFilter`

Новый изолированный компонент в `apps/client/src/features/search/` (выносим из
inline-кода `FilterBar.tsx`). Заменяет блок «Цена» (`FilterBar.tsx:418-448`).

### B.1 Контейнер — Radix `Popover` (не `DropdownMenu`)

`DropdownMenu` навязывает menu-семантику (arrow-key навигация, typeahead),
ломающую ввод в текстовых полях и перетаскивание слайдера. Поэтому **только
фильтр цены** переходит на Radix `Popover` (остальные фильтры остаются на
`Dropdown`). Создать тонкую обёртку `Popover`/`PopoverContent` в
`components/ui/`, стилизованную теми же токенами, что `DropdownContent`
(`fade-up rounded-xl bg-surface shadow-raised`, в Portal). Триггер —
существующий `TriggerButton` (пилюля + active-стейт).

### B.2 Вкладки

- **«Цена»** — активна и функциональна (сегмент-контрол под токены бренда).
- **«Ежемесячный платёж»** — присутствует, при выборе показывает плашку
  «Скоро» (без слайдера/полей). Не влияет на фильтрацию. Honest-заглушка, не
  фейковый контрол.

### B.3 Гистограмма

- Лёгкий SVG: столбики из `buckets` (высота ∝ `count`, нормировка по max
  count), бренд-красный `#e03c42`.
- Источник данных: `GET /search/price-distribution?currency=…&transaction_type=…`
  через RTK Query (lazy/обычный), ключ кэша = `(currency, transaction_type)`.
- **Graceful degradation:** нет данных / `max=0` / одна корзина → ровная
  база-линия; слайдер и поля продолжают работать (домен — дефолтные границы по
  валюте). Гистограмма — украшение, не блокер.

### B.4 Слайдер

- Radix `Slider` в range-режиме (две ручки), доступный из коробки
  (клавиатура + ARIA).
- Домен `[min, max]` из эндпоинта (фолбэк-дефолты по валюте, если данных нет).
- Верхняя ручка на `max` трактуется как «max+» (overflow): при значении на
  максимуме `priceMax` уходит как «без верхней границы» (не отправляем
  `price_max`), как Zillow «$10M+».
- Двусторонняя связь со слайдером ↔ поля Мин/Макс.

### B.5 Поля Мин/Макс + подписи

- Подписи «Мин» / «Макс» над полями; «–» между ними.
- Плейсхолдеры `от $ / до $`, символ валюты — из текущего `displayCurrency`.
- Числовой ввод; синхронизированы со слайдером; клемп в домен.

### B.6 Кнопки

- **«Применить»** (красная, бренд) → `setParams({ priceMin, priceMax, currency })`
  и закрывает Popover. Пустые границы не отправляются.
- **«Сбросить»** — очищает драфт и ценовые параметры.
- Драфт-стейт (вкладка/слайдер/поля) — локальный; URL обновляется только по
  «Применить» (а не по каждому движению ручки).

### B.7 Валюта и тип сделки

- Фильтр работает в `displayCurrency` (глобальный `useCurrencyPreference`).
- Смена сум/$ **или** типа сделки (Купить/Аrenда) → refetch гистограммы +
  сброс домена/драфта под новую валюту.

### B.8 Фикс корректности валюты (латентный баг)

`buildSearchParams` (`lib/api/listings.ts`): отправлять `currency`, когда задан
хотя бы один ценовой рубеж (`priceMin` или `priceMax`). Без ценового рубежа
`currency` не отправлять (как задумано в DTO — иначе исключим объявления другой
валюты без причины).

### B.9 i18n (ru/uz/en, узел `search.filters`)

Новые ключи:
- `priceTabList` — «Цена» (вкладка).
- `priceTabMonthly` — «Ежемесячный платёж».
- `priceTabMonthlySoon` — «Скоро».
- `priceMinLabel` — «Мин».
- `priceMaxLabel` — «Макс».

Переиспользовать существующие: `priceFrom` («от»), `priceTo` («до»), `apply`,
`resetAll`, `currencySymbolUzs`/`currencySymbolUsd`, `price`, `priceRange`.
Проверить ключи вручную (mock next-intl скрывает отсутствующие — известная
гоча проекта).

### B.10 Прочее

- Чип `ActiveFilters` для цены — **оставляем как есть** (уже обрабатывает
  `priceMin`/`priceMax`).
- Триггер-лейбл «Цена» / «Цена: min–max» — без изменений в логике.

## Краевые случаи

- Пустая/малая выборка распределения → ровная база, слайдер на дефолт-домене.
- Один бакет → корректная отрисовка без деления на ноль.
- Смена валюты/типа сделки во время открытого Popover → чистим драфт.
- Слайдер: клавиатура + ARIA (из Radix).
- Мобайл: Popover тянется по ширине вьюпорта.
- Overflow-ручка на максимуме → `price_max` не отправляется.

## Вне объёма

- Реальная ипотека / логика «Monthly Payment».
- Калькулятор «BuyAbility».
- FX-конвертация в фильтрации (MVP — без FX).
- Контекстная гистограмма (учёт района/комнат/полигона) — возможная будущая фаза.

## Критерии готовности (verify)

- **API:** `GET /search/price-distribution` отдаёт корректные бакеты по
  (валюта+сделка); сумма count+overflow = числу видимых объявлений; пустая
  выборка → `max=0`/пусто; невалидные параметры → 400; int-spec зелёные;
  openapi.public drift-check зелёный.
- **client:** фильтр цены выглядит как Zillow (вкладки, гистограмма, слайдер с
  2 ручками, Мин/Макс, «Применить»); гистограмма рисуется из эндпоинта и
  деградирует без данных; «Применить» пишет `priceMin/priceMax/currency` в URL
  и меняет выдачу; смена сум/$ перерисовывает гистограмму; смешивания валют
  больше нет; lint/build зелёные; i18n-ключи присутствуют во всех 3 языках.
