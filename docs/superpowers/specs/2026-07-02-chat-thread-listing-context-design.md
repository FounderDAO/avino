# Spec: объявление видно в списке диалогов чата (фото + название)

**Дата:** 2026-07-02
**Статус:** approved (дизайн утверждён)
**Затрагивает:** только `apps/client` (один PR)

## Контекст и цель

Тред чата уже привязан к объявлению на бэке (`ChatThread.listingId`, уникальность
`(listing, initiator, owner)`), и `GET /api/v1/chat/threads` уже отдаёт
`listing_preview` (title, thumbnail_url, price, currency, status) — **бэкенд не
трогаем**.

Проблема в UI (`apps/client/src/features/account/Inbox.tsx`): в списке диалогов
видно только имя собеседника и последнее сообщение. Продавец с несколькими
активными объявлениями (или клиент, общающийся с несколькими продавцами по
разным объектам) не понимает, о каком объекте диалог — название листинга видно
только в шапке уже открытого диалога.

## Решение (утверждено)

Утверждённый мок карточки диалога (вариант «фото объявления + строка с
названием», как Zillow/Airbnb):

```
[🏠фото] Тимур А.               12:40
        3-к кв, Юнусабад · $85k
        Вы: Когда можно…           ❶
```

## Изменения — `apps/client/src/features/account/Inbox.tsx`

1. **Аватар диалога — фото объекта**: `listing_preview.thumbnail_url`
   (скруглённый, `object-cover`, ~44–48px, как текущий круг). Фолбэк, когда
   фото нет, — текущий круг с инициалом собеседника.
2. **Карточка диалога — три строки**:
   - имя собеседника (`counterparty.name`, текущий `threadTitle`) + время;
   - **новая строка**: название объявления · цена
     (`listing_preview.title` + существующий `listingSubtitle`), truncate;
   - превью последнего сообщения + badge непрочитанных (как сейчас).
   Если `listing_preview == null` — строка объявления скрывается (деградация до
   текущего вида).
3. **Шапка открытого диалога**: рядом с существующей ссылкой
   «название · цена» добавить миниатюру фото (маленькая, ~32–40px) — симметрия
   со списком. Ссылка на `/listing/:id` уже есть — не меняется.

Типы уже готовы: `ApiThread.listing_preview.thumbnail_url`
(`src/store/api/chatApi.ts`). Новые i18n-ключи не нужны.

## Тесты / проверка

- Существующих unit-тестов на Inbox нет — проверка визуальная (dev-сборка,
  seed-chat) + `rtk lint` / `rtk tsc` / build.
- Кейсы: тред с фото; тред без фото (фолбэк-инициал); `listing_preview == null`
  (DELETED-листинг из истории — строка скрыта, аватар-инициал); длинные
  названия (truncate); мобильная ширина (один пейн).

## Вне скоупа

- Изменения API (`apps/api`) — не нужны.
- Мобильное приложение — уже получает `listing_preview` из API.
- Группировка диалогов по объявлению, поиск по диалогам.
