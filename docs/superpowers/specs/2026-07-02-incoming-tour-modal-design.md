# Модалка входящего запроса на тур + цвета кнопок действий

**Дата:** 2026-07-02
**Приложение:** `apps/client` (публичный портал)
**Раздел:** Аккаунт → Туры → «Запросы ко мне»

## Проблема

В секции «Запросы ко мне» (`features/account/Tours.tsx`) владелец объявления видит
только имя, телефон и дату/окно запроса. Сообщение от запрашивающего
(`TourRequestItem.message` — уже приходит с бэкенда) нигде не показывается, и не
видно, к какому объявлению относится запрос. Кнопки «Подтвердить» и «Отклонить»
выглядят одинаково (нейтральная обводка) — семантика действий не считывается.

## Решение

### 1. Модалка `IncomingTourModal`

Новый компонент `apps/client/src/features/account/IncomingTourModal.tsx`:

- radix-ui `Dialog` по паттерну `features/detail/TourRequestModal.tsx`
  (Overlay `z-[80]` c blur, Content `z-[81]`, `rounded-[20px]`, `bg-surface`,
  `shadow-raised`, анимация `fade-up`, крестик закрытия).
- Пропсы: `{ item: TourRequestItem | null; onClose: () => void }`.
  Модалка открыта, когда `item != null`. Никаких новых запросов к API —
  все данные уже есть в загруженном списке.

Содержимое:

- Заголовок «Запрос на тур» + статус-бейдж (как `StatusBadge` в списке).
- Имя запрашивающего; телефон — ссылкой `tel:`.
- Дата и окно: `requested_date` на `window_start`–`window_end`.
- Блок «Сообщение»: `item.message` с `whitespace-pre-wrap`;
  если `null`/пусто — «Без сообщения» цветом `muted-foreground`.
- Ссылка «Открыть объявление» → `/listing/{listing_id}` (локализованный `Link`).

Действия:

- `status === 'PENDING'` → кнопки «Подтвердить» и «Отклонить»
  (существующая мутация `useUpdateTourStatusMutation`, actions `CONFIRM`/`DECLINE`).
- Успех → модалка закрывается; списки обновляются существующей инвалидацией тегов.
- Ошибка → текст ошибки (`getApiError`) красным внутри модалки, модалка не закрывается.
- Кнопки задизейблены на время мутации.
- Другие статусы → режим просмотра, без кнопок действий.

### 2. Открытие из списка (`Tours.tsx`)

- Состояние `selected: TourRequestItem | null` в `Tours`.
- Строки **входящих** запросов кликабельны: `role="button"`, `tabIndex={0}`,
  Enter/Space открывают модалку, `cursor-pointer` + hover-эффект.
- Клики по инлайн-кнопкам действий — `stopPropagation`, модалку не открывают.
- Секция «Мои запросы» (исходящие) не меняется.

### 3. Цвета кнопок (и в строке, и в модалке)

- «Подтвердить» — заливка `bg-green` (#34c759), белый жирный текст.
- «Отклонить» — заливка `bg-red` (#e03c42), белый жирный текст, hover `bg-red-press`.
- «Отменить» у исходящих остаётся как есть (нейтральная обводка).
- Осознанное решение: белый текст на `green` ниже WCAG AA (~2.1:1) —
  оставляем токен `green` ради консистентности палитры (утверждено).

### 4. Переводы

Новые ключи `account.tours.*` в `messages/ru.json`, `en.json`, `uz.json`:
`modalTitle`, `message`, `noMessage`, `openListing`, `close`.

### 5. Тесты

`Tours.test.tsx` (+ при необходимости `IncomingTourModal.test.tsx`),
паттерн существующих тестов (vitest + RTL, мокнутые хуки RTK Query):

1. Клик по строке входящего запроса открывает модалку, сообщение видно.
2. «Подтвердить» в модалке вызывает мутацию `{ id, action: 'CONFIRM' }`
   и закрывает модалку при успехе.
3. Клик по инлайн-кнопке в строке не открывает модалку.
4. Не-`PENDING` запрос: модалка без кнопок действий.
5. `message: null` → показан текст «Без сообщения».

## Вне скоупа

- Модалка для исходящих запросов.
- Подгрузка данных объявления (заголовок/фото) в модалку.
- Изменения бэкенда — не требуются.
