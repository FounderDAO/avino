# Счётчики непрочитанного + звуковое оповещение (client)

**Дата:** 2026-07-02
**Область:** `apps/client` (публичный портал)
**Статус:** дизайн утверждён, готов к планированию

## Проблема

В личном кабинете и шапке нет индикаторов непрочитанного. Если пользователю
ответили в чате, изменился статус тура или пришло уведомление — он никак об
этом не узнаёт, пока сам не откроет соответствующую вкладку. Нужно:

1. Показывать, **что** и **сколько** непрочитано (сообщения, уведомления, туры).
2. Делать это заметно — глобально в шапке, чтобы пользователь замечал ответ на
   любой странице.
3. Проигрывать короткий звук, когда появляется что-то новое «для него».

## Решения (утверждены)

- **Где:** шапка (глобально, на всех страницах) + бейджи на вкладках кабинета.
- **Шапка:** ✉️ конверт (непрочит. сообщения → `/account/inbox`) + 🔔 колокольчик
  (непрочит. уведомления → `/account/notifications`), у каждой иконки свой красный
  бейдж. Рядом с существующим ❤️ избранным.
- **Туры:** бейдж = число входящих заявок в статусе `PENDING`, **только в боковом
  меню кабинета** (в шапке иконки туров нет). У туров нет read-state на бэке,
  поэтому `PENDING`-входящие — единственный надёжный сигнал «требует внимания».
  Смена статуса по исходящим турам и так приходит отдельным уведомлением.
- **Звук:** короткий сигнал при росте суммарного числа непрочитанного; тумблер
  «Звук уведомлений» в Настройках (по умолчанию **вкл**, состояние в localStorage).

## Данные

Отдельного endpoint для «сводки непрочитанного» на бэке нет. Считаем из
существующих ручек (`store/api/*`):

| Счётчик       | Источник                          | Формула                                  |
|---------------|-----------------------------------|------------------------------------------|
| Сообщения     | `chatApi.getThreads`              | `Σ thread.unread_count`                  |
| Уведомления   | `notificationsApi.getNotifications` | `meta.unread` (поле `NotificationsResult.unread`) |
| Туры          | `tourRequestsApi.getIncomingTours`  | `incoming.filter(s === 'PENDING').length` |

Все ручки Bearer-only → запросы идут с `skip: !isAuthenticated`.

## Архитектура

### Единый источник — хук `useUnreadCounts()`

`src/store/useUnreadCounts.ts`:

- запускает 3 запроса выше с `skip: !isAuthenticated`;
- возвращает `{ messages, notifications, tours, total }`
  (`total = messages + notifications + tours`);
- принимает опцию `pollingInterval` (по умолчанию `0` — только чтение из кэша).

RTK Query дедуплицирует подписки по ключу запроса: несколько подписчиков на один
endpoint дают один сетевой поллинг (берётся наименьший интервал). Поэтому:

- **`UnreadIndicators`** в шапке (всегда смонтирован в корневом layout) вызывает
  хук с `pollingInterval: 20000` и `skipPollingIfUnfocused: true` — это «двигатель»
  фоновой свежести счётчиков.
- **`AccountLayout`** вызывает тот же хук без поллинга — просто читает уже свежий
  кэш.
- **Inbox** сохраняет свои интервалы (10с треды / 6с сообщения), когда открыт —
  RTK возьмёт меньший интервал.

### Новые компоненты/модули

1. `components/ui/count-badge.tsx` — красная «пилюля»-счётчик: пропсы `count`,
   `max` (деф. `9` → «9+»), `aria-label`; возвращает `null` при `count ≤ 0`.
   Стиль переиспользует существующий бейдж избранного из `Header.tsx`.
2. `components/layout/UnreadIndicators.tsx` — две иконки-ссылки (`Mail`, `Bell`
   из lucide) с `CountBadge`. Владеет поллингом (вызов `useUnreadCounts` с
   интервалом) и эффектом «звук при росте». Рендерится в шапке только для
   залогиненных.
3. `store/useUnreadCounts.ts` — хук (см. выше).
4. `lib/notificationSound.ts` — `isNotificationSoundEnabled()`,
   `setNotificationSoundEnabled(on: boolean)` (localStorage `avino.notifSound`,
   деф. `true`), `playNotificationSound()`.

### Правки существующих файлов

- `components/layout/Header.tsx` — вставить `<UnreadIndicators />` в залогиненную
  ветку рядом с ❤️ (десктоп); в мобильном полноэкранном меню добавить счётчики к
  пунктам «Сообщения» / «Уведомления».
- `features/account/AccountLayout.tsx` — бейджи `CountBadge` у вкладок `inbox` /
  `notifications` / `tours` (данные из `useUnreadCounts()` без поллинга).
- `features/account/Settings.tsx` — реальный тумблер «Звук уведомлений» (persist в
  localStorage через `notificationSound`). Ставится отдельно от текущих мок-тумблеров,
  т.к. он реально работает.
- `messages/{ru,uz,en}.json` — новые ключи: aria-подписи иконок шапки, заголовок и
  описание тумблера звука.

## Звук

- Реализация — **WebAudio** (короткий двухтоновый «динь» генерируется кодом),
  без бинарного ассета; легко заменить на записанный файл позже.
- `AudioContext` создаётся лениво и `resume()`-ится при первом воспроизведении.
  Браузеры разрешают звук только **после первого взаимодействия** пользователя со
  страницей — до этого `playNotificationSound()` — no-op (ожидаемо и приемлемо).
- **Триггер (в `UnreadIndicators`):** держим `prevTotalRef`.
  - Предыдущего значения нет (первый успешный ответ) → ставим базовую линию
    **без звука**.
  - `total` вырос относительно предыдущего → `playNotificationSound()` (если
    включено в настройках).
  - `total` не изменился или уменьшился → тишина.
  - Шапка смонтирована постоянно → `prevTotalRef` переживает навигацию между
    страницами, ложных сигналов на логине/переходах нет.

## Крайние случаи

- **Гость** — иконки шапки и бейджи скрыты, запросы `skip`.
- **Переполнение** — «9+» в шапке (`max=9`), до «99+» в кабинете (`max=99`).
- **Скрытая вкладка** — поллинг приостановлен (`skipPollingIfUnfocused`), звук не
  спамит при возврате (базовая линия обновится при следующем ответе).
- **Звук выключен в настройках** — `playNotificationSound()` — no-op; бейджи
  работают как обычно.

## Тестирование (по образцу существующих `*.test.ts` в `features/account`)

- `useUnreadCounts` — суммирование `unread_count`, `meta.unread`, фильтр `PENDING`,
  скип для гостя, `total`.
- `notificationSound` — enable/disable/persist в localStorage, деф. `true`,
  `play()` как no-op при выключенном.
- `count-badge` — рендер числа, порог «9+»/«99+», `null` при `count ≤ 0`,
  наличие `aria-label`.
- Логика «звук при росте» — базовая линия без звука, динь при увеличении `total`,
  тишина при уменьшении/без изменений.

## Вне области (YAGNI)

- Серверный контракт на настройки уведомлений (звук держим локально).
- Real-time транспорт (WebSocket/SSE) — остаёмся на поллинге.
- Read-state для туров на бэке — считаем `PENDING`-входящие.
- Пуш-уведомления браузера / вкладочный `title`-мигатель — отдельная история.
