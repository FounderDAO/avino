# Счётчик звонков по объявлению — дизайн

**Дата:** 2026-07-03
**Статус:** утверждён к реализации

## Проблема

Владелец объявления и админ видят счётчик просмотров (`views_count`), но не
видят, сколько раз потенциальные покупатели проявили намерение позвонить.
Нужен счётчик звонков по каждому объявлению — в первую очередь для мобилки.

## Что считаем

Считаем **намерение позвонить** = клик по раскрытой `tel:`-ссылке в карточке
контакта. Факт состоявшегося звонка (дозвонился ли человек) из браузера узнать
нельзя — это ограничение принято осознанно, так работают все доски объявлений.

**Почему не «boolean-тумблер на одной кнопке»:** в текущем UI уже два разных
элемента — кнопка «Показать телефон» (раскрывает номер) и, после раскрытия,
`tel:`-ссылка (клик открывает звонилку). Искусственный guard «был ли показан
номер» не нужен: состояния уже разделены. Раскрытие номера НЕ считаем —
считаем только клик по самой ссылке.

## Архитектура

Полное зеркало существующего паттерна просмотров: поле `viewsCount` /
`POST /listings/:id/view` (`listings.service.ts:775`). Новое поле `callsCount`,
новый эндпоинт `POST /listings/:id/call`, инкремент только для `ACTIVE`.

### Дедупликация

Каждый тап по номеру = +1 (без дедупликации), как у просмотров. Метрика
интереса, а не уникальных пользователей.

## Поток данных

Мобилка: тап «Показать телефон» → номер раскрыт (`phoneShown=true`) → тап по
номеру → открывается звонилка **и** параллельно `POST /listings/:id/call`
(без ожидания ответа) → `calls_count + 1` в БД → виден владельцу в «Мои
объявления» и админу в детали объявления.

## Обработка ошибок

Как `ViewTracker`: 404 (объявление не ACTIVE) и сетевые ошибки молча глотаем —
на набор номера не влияют. Владелец своего объявления кнопку телефона не видит
(ветка `isOwner` в `ContactCard`), самонакрутки нет.

## Тесты

- **API** (`listings.service.spec`): `registerCall` инкрементит `calls_count`
  для ACTIVE; кидает 404 для не-ACTIVE (копия теста `registerView`).
- **Client** (`ContactCard.test`): клик по раскрытой `tel:`-ссылке дёргает
  `registerCall`; отклонение мутации не ломает ссылку/навигацию.

## Известные ограничения

- Порядок «клик 1 = показать, клик 2 = считать» держится на локальном
  `phoneShown`, который сбрасывается при перезаходе на страницу. Для метрики
  интереса это приемлемо: каждый визит с намерением звонка = +1.
- Считается намерение (клик), а не факт звонка.
