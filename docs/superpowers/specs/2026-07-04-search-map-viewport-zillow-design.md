# Дизайн: Zillow-поведение карты на /search + унификация с /map

Дата: 2026-07-04
Статус: утверждено Team Lead (сессия 2026-07-04)
Скоуп: только `apps/client` (backend не меняется)

## Проблема

На /search карта пассивна: пан/зум не влияет на выдачу, клик по маркеру лишь
подсвечивает карточку в списке. Пользователь ожидает поведение Zillow
(проверено вживую на zillow.com 2026-07-04):

1. Без активной границы региона список = видимая область карты; каждый
   пан/зум (с дебаунсом) обновляет выдачу и счётчик; bbox пишется в URL.
2. Пока граница региона активна — движение карты выдачу НЕ меняет.
3. Клик по пину → мини-карточка объявления поверх карты.
4. Клик по мини-карточке → детали открываются оверлеем поверх выдачи,
   «назад» возвращает к списку.

На /map всё это уже реализовано (`MapSearch` + `/search/bounds` +
превью-оверлей + intercepting-модалка). Задача — перенести на /search и
вынести общую логику, чтобы страницы не разъезжались.

## Решения (утверждены)

| Вопрос | Решение |
|---|---|
| Скоуп | /search + унификация общей логики с /map |
| Гео-приоритет | Как у Zillow: полигон/район/регион держат выдачу; viewport-режим только без гео-фильтра |
| Архитектура | Общий хук `useViewportSearch` + общий компонент `MapPreviewCard` в `features/map/` |
| bbox в URL | Да: `sw_lat, sw_lng, ne_lat, ne_lng` через shallow `history.replaceState`; SSR понимает bbox (zoom выводится из bbox через `map.setBounds`) |

## Режимы выдачи на /search (приоритет сверху вниз)

1. **Полигон (территория)** — как сейчас: нарисованная территория держит
   выдачу (`/search/polygon`, limit=100), пан/зум её не меняет.
2. **Гео-фильтр (region_id/district_id)** — как сейчас: выдача по фильтру
   (SSR + keyset), карта пассивна (autoFit). Снятие фильтра чипом →
   возможен viewport-режим.
3. **Viewport-режим (нет гео-фильтра)** — новое: первый ЖЕСТ ПОЛЬЗОВАТЕЛЯ
   (пан/зум) переводит выдачу в режим «список = видимая область»:
   - `boundschange` (существующий дебаунс 450 мс в MapView) →
     `GET /api/v1/search/bounds` со всеми активными не-гео фильтрами + bbox,
     `limit=100`;
   - список справа = bounds-выдача; счётчик результатов обновляется;
   - рендер списка батчами по 24 с локальной кнопкой «Показать ещё»
     (без дополнительных сетевых запросов; серверный keyset в
     viewport-режиме не используется — консистентно с полигон-режимом);
   - маркеры на карте = те же (до) 100 результатов;
   - autoFit отключается (карта не перескакивает) — как на /map.

Программные движения карты (autoFit при первичной загрузке, panTo от
`map_hover_recenter`) viewport-режим НЕ активируют — только жест
пользователя.

## bbox в URL

- При каждом bounds-обновлении: shallow `window.history.replaceState` с
  `sw_lat, sw_lng, ne_lat, ne_lng` поверх текущих фильтров (НЕ
  `router.replace` — он дёргал бы серверный ре-рендер страницы на каждый
  пан карты; shallow-обновление поддержано App Router нативно).
- SSR `/search/page.tsx`: если в URL есть валидный bbox и НЕТ гео-фильтра —
  первая выдача рендерится сервером через bounds-поиск (limit=100), карта
  открывается на той же области (initialBounds → `map.setBounds`; zoom
  выводится из bbox, отдельный параметр не нужен).
- Если bbox в URL сосуществует с гео-фильтром — гео-фильтр побеждает,
  bbox игнорируется (и вычищается из URL при следующем replace).

## Мини-карточка при клике на пин

Новый общий компонент `apps/client/src/features/map/MapPreviewCard.tsx`:

- оверлей поверх карты (absolute у нижнего края области карты, как сейчас
  на /map), внутри — существующий `PropertyCard` + кнопка ✕;
- клик по пину → `previewId` → показать; ✕ или клик по другому пину →
  скрыть/заменить;
- клик по карточке — это уже `<Link href="/listing/[id]">` → intercepting
  route `@modal` → `ListingModal` (работает из коробки, новый код для
  модалки не нужен).

## Общий хук

`apps/client/src/features/map/useViewportSearch.ts` — вся общая логика:

- вычисление режима (polygon > geo-filter > viewport/static);
- lazy bounds-запрос с прокинутыми фильтрами;
- previewId state;
- колбэки для MapView (`onBoundsChange`, `onSelect`).

Используют оба потребителя:

- `features/search/SearchResults.tsx` (/search) — подключает хук, прокидывает
  `onBoundsChange`, рендерит `MapPreviewCard`, обновляет счётчик и список;
- `features/map/MapSearch.tsx` (/map) — рефакторится на хук + общий
  `MapPreviewCard` (поведение /map не меняется).

## Ошибки и краевые случаи

- Пустая область → пустой список + существующее состояние «ничего не найдено».
- Ошибка bounds-запроса → toast через существующую мидлварь; предыдущий
  список не очищается.
- Слишком крупный zoom-out: ограничений площади у `/search/bounds` нет,
  limit=100 защищает ответ.
- Антимеридиан `/search/bounds` не поддерживает — для Узбекистана не
  актуально.

## Backend

Без изменений. `/search/bounds` уже наследует все фильтры Фазы 2
(transaction_type, property_type, price, rooms, bathrooms, parking,
amenities, area, lot_area и т.д.).

## Тестирование

- Vitest (apps/client): хук `useViewportSearch` — гео-приоритет (полигон/
  район глушат bounds), активация по жесту, формирование параметров;
  рендер/закрытие `MapPreviewCard`.
- Живая проверка на docker-стенде: пан/зум обновляет список и счётчик,
  bbox в URL, refresh сохраняет область, пин → мини-карточка → модалка.
